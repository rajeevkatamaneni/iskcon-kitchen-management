## Not done / needs Rajeev

- **No hand smoke test in a real browser.** Staging is off limits and memory is tight, so I did not run the app. Everything is proved in jsdom only.
- **`Field`'s `required` never reaches the input.** This is the finding at the top. Rajeev's ruling says required fields carry `required` on the element, and on sign-in, Add a temple and Edit a temple they don't. So a blank temple name, admin name or coordinate goes to the server, and blank coordinates are sent as 0. There are two ways to fix it:
  1. Add `required` to each input in these three pages, as meal kinds does. It is a page-only change, but the existing `tenant-new` tests submit with blank coordinates and a blank admin name and email, so they would need those filled in.
  2. Have `Field` pass `required` through to the input's props. That fixes every `Field` in the app at once, but `Field.tsx` is shared and other screens' tests may submit blanks.

  Option 2 is my recommendation, because a label that says "(required)" over a box that isn't required is the same defect wherever `Field` is used. It needs a task of its own with a sweep.
- **Giving's amount box has no `min` or `type="number"`.** The only guard is the disabled Give button. Pressing Enter in the box might still submit a negative amount, and I did not verify that either way.
- The brief's "public giving page, used by devotees who are not signed in" no longer matches the code. That page was removed on 2026-08-29.
