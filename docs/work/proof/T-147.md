## What was built, and the three decisions

The pill is unchanged: same classes, the users icon, "5 of 8" and the same `sr-only` sentence. It no longer has a `title`. It and a new `<InfoHint text="3 staff and 2 volunteers, of 8 needed" label="crew" />` now sit together in one wrapper, `<span className="inline-flex items-center gap-1.5">`. The hint text is the exact string the `title` used to hold.

**Beside the pill, not inside it.** Inside has two problems. The InfoHint button is 20px (`h-5 w-5`), but the pill is sized to a 16px `text-xs` line, so the pill would grow about 4px taller than the Recorded badge next to it. And the button's grey ring would sit on the warning fill, while the tooltip sentence would inherit the pill's `font-semibold`. Beside it, as a loose item in the meal header row (`flex flex-wrap items-baseline gap-x-3`), has a different problem: at phone width the row can wrap between the pill and the "i", leaving the "i" at the start of the next line. The non-wrapping wrapper avoids both. The pill looks exactly as it did, and the "i" stays next to it.

**Label (first pass, since changed; see "Contract widening, 2026-09-12" below): `"crew"`, so the button's name was "More about crew", not "More about crew for Lunch".** `CrewPebble` isn't given the meal's name, and the crew row it does get can't stand in for it. `MealServices` finds that row by meal kind alone (line 174, `c.mealKind === meal.mealKind`), so every event would be named "crew for Event". It is also null when the crew count was refused. Naming the meal properly needed the call site at line 428 to pass it in, and that line was outside the original contract. It has since been widened and done.

**Nothing is announced twice.** The pill reads "5 of 8 people rostered of the number this meal takes". The button reads "More about crew for Lunch". The staff-and-volunteers sentence is in the page only while the tooltip is open, as the tooltip's own text, and nowhere else. The third test checks exactly one text node holds it and that node is the `role="tooltip"`. Before this change, the sentence reached assistive technology only as a `title` on a plain span, which screen readers often ignore.

**ShiftPebble (out of scope, not changed):** I think it is partly the same defect. Its `sr-only` "for {title}" covers screen-reader users. A sighted keyboard or touch user still can't see which shift a "2 of 5 signed up" is, and on a past day, where the pill is a plain span, there is no other way to find out. On an open day the button opens the layer, which shows the title, so it matters less there. Left for the sweep.

## Acceptance criteria

1. **The crew pebble carries no `title`.** Test 1 checks the pill has no `title` attribute and that nothing on the day has a `title` containing "volunteers". It fails under the control with `Received: title="3 staff and 2 volunteers, of 8 needed"`.
2. **The breakdown is reachable by keyboard.** The other InfoHint tests (`field-kit.test.tsx:31-34`, `settings-payments.test.tsx:528-533`) find the button by name `More about …` and read `getByRole("tooltip")`, but they open it with `mouseOver`, which proves nothing about a keyboard. Test 2 uses the same queries but opens by focus alone. It checks the button is a `BUTTON` with `type="button"`, is enabled, and has `tabIndex >= 0` (so it is in the tab order). Then `act(() => hint.focus())`, `document.activeElement === hint`, and the tooltip reads "3 staff and 2 volunteers, of 8 needed". Escape removes it. The project has no `user-event`, so a real Tab press isn't simulated. Focusable-in-order plus opens-on-focus is the two halves of it.
3. **"N of R" and the warning tone are unchanged, and a meal with no required count has no pebble.** Test 4: "5 of 8" has `bg-warning-bg` and `text-warning`. Test 5: "8 of 8" has `bg-sunken` and no warning. Test 6: with `crewRequired: null` there is no `.ti-users` and no "More about crew" button. Test 3 also checks the pill's text is exactly "5 of 8 people rostered of the number this meal takes". `planner-shift` still finds "5 of 8" in the day's text.
4. **The three granted tests still pass.** planner-shift 8/8, meal-correction 11/11, meal-recording 13/13, in the run above.
