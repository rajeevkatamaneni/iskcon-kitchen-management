# T-216 — a required query value left out is KMS-400001 naming the field, not KMS-500001

**Files changed:** (all inside the contract)

- `backend/src/main/java/org/iskcon/kms/error/GlobalExceptionHandler.java` — new
  `handleMissingRequestValue` for `MissingServletRequestParameterException`, placed after the
  type-mismatch handler it mirrors. 400, `ErrorCode.VALIDATION_FAILED` (KMS-400001), one field error
  `{field: <parameter name>, message: "This can't be left empty."}`, `log.warn` with reference,
  method, path and parameter name. No incident id, no type name in body or log. Javadoc says why,
  including why the parent `MissingRequestValueException` is not caught (it also covers
  `MissingPathVariableException`, which is our own mapping bug and should stay KMS-500001).
- `backend/src/test/java/org/iskcon/kms/error/GlobalExceptionHandlerTest.java` — 3 tests: missing
  value, empty value (`missingAfterConversion=true`), and no leak plus FieldErrorMessageTest's
  sentence rules applied to the generated message.
- `backend/src/test/java/org/iskcon/kms/error/ErrorResponseIT.java` — 1 test over real HTTP: the
  existing `/test-errors/filter` endpoint (required `@RequestParam Unit unit`) called with no `unit`.
- `backend/src/test/java/org/iskcon/kms/meal/MealCrewIT.java` — 1 test: `/api/v1/meal-crew/at?date=2026-09-21`,
  no `readyBy`, as the temple admin (has MANAGE_MEAL_PLANS; the same user already calls `/at` in this class).
- `docs/work/proof/T-216.md` — this file.

Not touched: `ErrorCode.java`, `MealCrewController`. No new code used.
