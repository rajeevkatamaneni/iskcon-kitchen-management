# T-157 — a phone number typed as "+91 98765 43210" is accepted everywhere the E.164 rule applies, and stored bare

**State: proven.** Both negative controls went red and restored byte for byte. The final runs are green.

## What changed, in one paragraph

Spaces, dashes and invisible characters are now removed before the phone rule is checked, on the server and on every screen that sends to one of those fields or to Firebase. What gets stored is the bare E.164 number. The regexp is unchanged, and so is `GlobalExceptionHandler`. A typo is still refused with `KMS-400003`. A box of spaces is still a missing number.

## Mechanism, and why

**Server:** `config/PhoneNumberDeserializer`, a Jackson deserializer, is put on each field with `@JsonDeserialize(using = PhoneNumberDeserializer.class)` next to its `@Pattern`. Jackson builds the record with the stripped value, so Bean Validation sees the stripped value.

I chose this over compact constructors for three reasons:
- The leniency sits next to the rule it serves.
- There is one implementation, not seven call sites into a helper that would have no home inside the contract.
- It only changes JSON input, which is where people's typing arrives. The records' Java constructors keep their meaning. That matters on `UpdateStaffRequest`, where null and blank mean different things.

The cost is that a new phone field has to remember the annotation, just as it has to remember the `@Pattern`.

**What is removed** is the same set on both sides:
- every kind of whitespace, `[\s\p{Z}]`, including the non-breaking space;
- dashes, `\p{Pd}` (a phone keyboard turns a hyphen into an en dash);
- invisible format characters, `\p{Cf}`: zero-width space, byte-order mark, and the direction marks Android adds around a copied contact.

**Brackets are not removed.** They usually hold a trunk 0 that should be dropped once the country code is written: `+91 (0) 80 …`. Removing the brackets but keeping the 0 would store a number that passes the rule and rings nobody. Refusing it costs one retype.

**Dots are not removed** either. Nobody writes an Indian number with dots.

**Nothing else is removed.** The old `normalizePhone` in `tenants/new` kept only `+` and digits. That turned `+91 98765 4321X` into a well-formed wrong number. The shared helper is narrower on purpose, so that typo is now refused.

**Blank:** a box of spaces becomes `""`, never null. `""` still fails `@NotBlank` where a number is required, so the reply stays `KMS-400001` with "Enter a phone number." Where the number is optional, `""` still fails `@Pattern`, exactly as a typed space did before.

**Frontend:** `frontend/lib/phone.ts` exports `normalizePhone` (strips the same set) and `isE164` (normalise, then apply the server's regexp). The copy of `normalizePhone` in `tenants/new` is gone, and the regex literals in `register` and `JoinTempleForm` are replaced.
