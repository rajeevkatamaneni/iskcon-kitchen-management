## Not done, deviated, or needs Rajeev

**1. One existing expectation was changed, deliberately, and it is a behaviour change.**
`CommunicationRetryIT.aRetryInFlightIsNotRetriedAgain` asserted `KMS-400138` for a second press while
the first retry was still on its way. It now asserts `KMS-400142`. That case is exactly what finding 6
says the old sentence got wrong — the copy has *not* been delivered, it is in flight — and the test's
own name ("with the first still on its way") describes the new code better than the old one. Flagged
because it is a changed contract, not a new one.

**2. `SENT` is treated as delivered, not as in flight.** The dispatch says PENDING; I kept to that and
did not widen it. The reason it should stay that way: `notifications.status` runs
PENDING → SENT → DELIVERED, but only WhatsApp has a delivery webhook. An emailed newsletter can sit at
SENT for ever, so counting SENT as "still on its way" would make KMS-400142 permanent for email and
KMS-400138 unreachable. A judgement, recorded rather than buried: if Rajeev wants "handed to the
relay, not yet confirmed" said differently, that is a fourth sentence, not a change to this branch.

**3. A pre-existing flaky test in a file outside my contract — `CommunicationIT`, not touched.**
One run of the pair came back 21/22 with
`CommunicationIT > an unsubscribe link works with no session, and a tampered one does nothing FAILED
— Status expected:<400> but was:<200>` (`CommunicationIT.java:317`). The immediately preceding and
following runs were both 22/22, and the mechanism is in the test rather than in the product: it forges
a token with `token.substring(0, len - 2) + "xy"`, but the token's tail is base64url of a 32-byte HMAC
tag — 43 characters, of which the last carries **two unused bits the decoder ignores**. Verified:

```
tag chars: 43 last two: h8
chars decoding to the same 32 bytes as 8 : 89-_
```

So whenever the tag's second-to-last character is already `x` and its last is one of the four sharing
`y`'s bits, the "tampered" token decodes to the identical tag and is correctly accepted — about one
run in 1024. **Nothing here is a security defect** (the forger gains nothing; the same tag verifies),
but the test will keep failing occasionally on CI. The fix is one character — tamper in the middle of
the tag rather than at its end. `CommunicationIT.java` is not in my paths, so it is left alone and
raised here.

**4. No hand smoke test.** Commandment 5 asks for one where a task adds a user-facing surface. This
task adds no new screen — one audit-log label and three error sentences — and I have no deployed
build of this branch to drive, so the retry button and the audit row have **not** been pressed by
hand. The label and the filter option are covered by `audit.test.tsx`, and the three sentences by the
ITs asserting message and next-step text; the audit row rendering on staging is worth thirty seconds
