**How it was measured.** Every number below is from `getBoundingClientRect` / `getComputedStyle` /
`Range.getClientRects` (line counts = distinct line tops of the text), run with `javascript_tool`
on the screen loaded in a same-origin iframe of the stated width, in my own tab. "Before" figures
were measured by putting the old layout back on the live page for the measurement only (restoring
the old `grid-template-columns`, row gap, legend class, etc. via inline style), not by reverting
files. Anything not measured is marked **not verified**. Screenshots were used to find problems, not
to report them.

`resize_window` was tried once at the start; it resizes the window every agent shares, so it was put
back to 1512×900 straight away and not used again. Nothing that writes data was pressed; the only
click was the Leave filter tab "Everything".

   them caps, not widths. Measured at 1280: /users Name column 347px for ≤126px of names, Email
   column 132px with every email on 2–3 lines; /staff Name 265px for ≤118px, emails 3 lines. The rule
   says "the width its longest content needs, up to a cap".

   `px-4 sm:px-8`. Measured at 390: page content starts at x=32, the drawer bar's content at x=16
   (header padding 16px).
3. `components/ds/FocusScreen.tsx` header — measured 145px tall at 390 (85px at 768), because the
   actions wrap under the title. Consider keeping them beside the title on a phone.
