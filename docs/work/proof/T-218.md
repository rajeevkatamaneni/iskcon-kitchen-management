**Acceptance criteria:**

1. Labels. The form says "This recipe makes" and "Measured in". The detail-page Fact says "This recipe makes". Server messages now read "Enter how much this recipe makes." and "Choose what this recipe is measured in." The second was "Choose a yield unit." and was not in the brief; I changed it so it matches the new label. "One person eats" and "Portion unit" are unchanged. Covered by `recipe-form-units` "the labels", and a grep finds no user-visible "base yield" left in frontend or backend. Mentions remain only in docs/stories and code comments.
2. "Measured in" offers Kg, L and pieces only (test). An older recipe saved in GM or ML keeps its own unit as an extra option, so it opens and saves unchanged. The test saves a 5000 gm recipe with a 50 gm portion and gets the same values back, and the backend test shows a GM recipe with a KG portion is still accepted. None exist in the data I could check.
3. The portion unit is locked to the recipe's family: KG allows Kg or gm, L allows L or ml, pieces allows pieces only (test). Changing "Measured in" clears a portion unit that no longer fits and keeps one that does (test). The backend has a class-level `@PortionFitsYield` that files the error against `perHeadUnit` and answers KMS-400001 with a fieldErrors entry, the same pattern `NotAtZeroZero` uses. The message is "A recipe measured in Kg takes its portion in Kg or gm." (or L/ml, or pieces). A blank portion is still allowed. `RecipeIT` covers create, edit, and the accepting cases.
4. Feeds line: 270 L at 350 ml gives "This recipe feeds about 771 people at 350 ml each." (test). It uses `convertQuantity` for the conversion and `cooksQuantity` for the portion, and groups digits en-IN ("14,286" in a test). It only appears once both amounts and both units are filled (test). Below one person it says "fewer than one person", and exactly one says "1 person".
5. Amber `InlineNotice tone="warning"` (bg-warning-bg) appears under 5 or over 5,000, with Rajeev's exact sentences. Save still submits (test). Exactly 5 and exactly 5,000 get no warning (test). The warning is judged on the rounded figure, so it always agrees with the number on screen.
6. The hint uses the existing `HintedField`/`InfoHint` ⓘ next to "This recipe makes", with the exact sentence. The test focuses the ⓘ and reads the tooltip.

Add-on: the detail page's "Scale to" box now shows `unitLabel(recipe.baseYieldUnit)` right after the box and before Scale. The box, unit and Scale sit in a row that does not wrap; only Reset can drop underneath. The box went from w-28 to w-24 to make room. Tests check "L" and "pieces" appear right after the box and before Scale.
