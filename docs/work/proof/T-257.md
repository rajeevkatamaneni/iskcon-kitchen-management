**Rulings used** (the clarifier said NOT SETTLED on both; these are the conductor's calls, 2026-09-19):
1. On Add to inventory, the value is required only when a count above 0 is typed. The rule is "whenever a person adds stock", and a blank or 0 count adds none.
2. The box is visible but disabled until an ingredient is chosen, labelled "What it would cost to buy today (₹)". After that it reads "(₹ per <unit>)" and is pre-filled.
Also, from the brief: on the item page the box appears for a positive change with ANY reason, because the server requires it for any positive quantity (`requiresStockValue` = `quantity > 0`).

**Details**
- Unit word: `unitLabelFor(1, stockUnit)`, so it reads Kg, gm, L, ml, or "piece". It always names the ingredient's stock unit, never the unit the count is typed in, because the server stores the value per canonical unit.
- Required: `required` plus `data-more-than="0"`. `Form` then says "… is required" for a blank box and "… must be more than 0" for 0, in red beside the box. The server's KMS-400161 is shown through `ErrorNotice`, as every refusal on these screens is.
- Pre-fill: only into an empty box, and it never overwrites what someone has typed. If the lookup fails, the box stays empty, still required. The loader is held in a ref, so a `getToken` that changes identity doesn't refetch or clear the box.
- ⓘ hint: "The price of one Kg today. We fill in the preferred vendor’s list price, or else the market rate. Saving it updates the market rate."
- Market-rate display and editing on the ingredient page (Q-10) is not built.
