## What it does

**The rule.** When the person answers "Use Ginger", the part of the library's name that isn't "Ginger" goes on the recipe line as its note. It does not use the word list.

- "Ginger, peeled" + Ginger gives "peeled". The same for Mustard/split, Curd/thick, Semolina/fine, Jaggery/dark, Cashew/broken, Sugar/powdered and Ghee/hot.
- With a comma, the part before the first comma must be the chosen name. The matcher decides that, so plurals, case and a one-letter slip count ("Gingers, peeled" and "Jaggary, dark" both work). Every segment after the comma becomes the note, as written, joined with ", " ("Rice, basmati, aged" + Rice gives "basmati, aged"). Case is kept as written ("Curd, Thick" gives "Thick"), the same as the word-list split does for a comma tail.
- Without a comma, the chosen name must be the first words or the last words of the typed name. The words on the other side become the note, in lower case: "Thick curd" + Curd gives "thick", and so does "Curd thick". Lower case matches what the split does with "Sour curd". A name in the middle is not taken apart ("Hot curd rice" + Curd gives no note). Today's matcher never calls "Thick curd" close to "Curd", so this branch only matters if the matcher changes.
- Nothing left means no extra note:
  - a spelling ("Tomatos" + Tomato)
  - a spacing ("Greenchilli" + Green chilli)
  - the bare side of a bare-and-qualified pair ("Tomatos" + "Tomato, ripe")
  - two varieties ("Tomato, ripe" + "Tomato, red")
- The rule tries the name the match was made on (an alias, if it was one) first, then the ingredient's own name.
- **Both notes at once.** If the word list also produced a note, both are kept, in the order the library wrote them: "Rice, basmati, soaked" + Rice gives "basmati, soaked".
- **Where the word list already produced a note and nothing is left over, the saved note is unchanged.** The Tomatos · chopped tests pass unedited.
- **"It's a different ingredient" is unchanged.** It creates "Ginger, peeled" whole, and the line has no note (tested).

**`ImportCloseMatchView.note`** is now the note the line gets on "Use". The GET list and the KMS-400156 details both carry it. When two lines share one question, each line still gets its own note.

**The dialog** (the clarifier ruled that R-DUP-2's question stays word for word, so the note is not added to it):

- **Heading:** the name as the library wrote it. The note is added only for the parts the name doesn't already contain, matched as whole words. So it reads "Ginger, peeled", not "Ginger, peeled · peeled", and "Tomatos · chopped" as before.
- **Question:** "Did you mean Ginger?", unchanged.
- **New line under the question, only when there is a note:** "The line will read “Ginger · peeled” if you use it." My wording, written with the ux-writing skill. It is 10 words and says the outcome before the answer. It starts with "The line", not the ingredient name, so "Tomato, ripe" doesn't produce a comma pile-up.
- **Answered:** "Using Ginger · peeled.", which was "Using Ginger." It uses the R-DUP-1 display form.
