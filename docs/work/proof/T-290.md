## What was built

**D1.** Label is R-INV-3's wording, then what came: `PO-2026-0051 · delivered 19 Sept · received by
Karuna Murti Das · 45 Kg`. One line: its delivered quantity in the Delivered column's words ("4 × Bag
(25 Kg)" for a pack order). Several lines: "4 items". Added to every label, so they all read alike, not
only the ones that clash. If two still match (same order, day and amount), they get "· 1st that day" /
"· 2nd that day". I couldn't use the time: `BillableDeliveryView.receivedOn` is a date, and changing it
means touching `api.ts` and the record, which is outside the contract. Sort: order number, then day
(page, stable sort); server `ORDER BY po.po_number, r.received_at, r.id` (was `r.received_at DESC, r.id`).

**D2.** Delivery lines: Billed qty is one card column beside Amount, and Rate goes under it, as in the
mock. Lesser-evil choice, recorded in the code comment: **a line billed in a pack still spans the card**,
because box 80 + gap 8 + "× Bag (25 Kg)" list 122 = 210px doesn't fit the 171px half. I tried letting only
the list wrap inside the half column first. It measured worse: that card was 341px, not 313, with
171 × 76px empty under Amount. So I reverted it. The span follows the chosen unit: switch the rice to Kg
and it goes back beside Amount (tested). `max-lg:flex-wrap` stays as a safety net for narrower phones: at
360, "pieces" (171px) wraps inside its 156px half, with no overflow. Direct invoices are unchanged and
keep the mock's direct table, where Billed qty spans the card.

**D3.** Billing deliveries: the tick boxes moved out of the slot beside Vendor and now sit full width
under the single boxes. From 1280 up the four boxes share one row (`xl:grid-cols-[2fr_1fr_1fr_1fr]`), so
the header is no taller than before. Below 1280 they sit two to a row. Direct mode is exactly the mock
(Vendor | Description, then number | date | due). The mock has no picker, so no drawn layout is departed
from. The only change is that the picker no longer sits in the dropdown's slot.
