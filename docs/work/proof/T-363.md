## There is no stash, and why

The instruction was `git stash push -u -m "T-363-wip"`. **I did not run it, because it would have
taken the release with it.** The worktree holds ~150 uncommitted files of Epic 12 kitchen and menu
work, and every file I had edited except four is also edited by that work — `frontend/app/today/page.tsx`,
`frontend/app/planner/page.tsx`, `frontend/components/planner/MealServices.tsx`,
`backend/.../MealPlanService.java`, `backend/.../today/TodayService.java` and
`frontend/__tests__/today.test.tsx`. A bare `git stash push -u` would have parked the whole release;
a path-scoped `git stash push -u -- <my files>` would have parked those files' *entire* diff against
HEAD, kitchen work included, and left them at HEAD. Either one loses work Rajeev has already verified.

So the edits were separated by hand instead, and proved separated:

- For the four files whose whole diff against HEAD was mine — `frontend/app/kitchens/page.tsx`,
  `frontend/components/ds/PeriodNav.tsx`, `backend/.../meal/OutsideCommitment.java`,
  `backend/.../meal/MealPlanController.java` — `git checkout HEAD -- <file>`.
- For `frontend/app/planner/page.tsx`, my three hunks were cut out of `git diff HEAD -U2` into a
  patch and reverse-applied (`git apply -R`), which restores the deleted `OutsideCommitments`
  component byte-exactly rather than by retyping it. The fourth hunk (the week tile's per-kitchen
  dish grouping) is Epic 12's and was left.
- For `backend/.../meal/MealPlanService.java`, the removed `outsideCommitments()` method was spliced
  back from `git show HEAD:` — again byte-exact, not retyped.
- Everything else was reversed by exact-string replacement, each one asserted unique before it ran.

## What the parked patch contains

1. **The planner's *Upcoming outside commitments* section is gone** — the `OutsideCommitments`
   component, its render under all three views, and the now-unused `OutsideCommitment` and
   `components/ds/table` imports, replaced by a comment carrying Rajeev's words and the reason.
2. **`GET /api/v1/meal-plans/outside-commitments` is gone**, with `MealPlanService.outsideCommitments()`.
   Tombstone comments left at both sites. `OutsideCommitment` the record stays, with its javadoc
   rewritten to say Today reads it now.
3. **`TodayView.upcomingOutside`** added to the Java record, filled by a new private
   `TodayService.upcomingOutside(today)` that reuses the removed endpoint's SQL, narrowed to
   `plan_date > today` (today's own outside meals are already in the meals card above, and listing
   them twice would say the temple had two) and `<= today + 14 days`. A fortnight is bounded by
   meaning rather than by a row cap, so nothing is silently hidden. It takes a `JdbcTemplate`, which
   is a deliberate exception to that class's "ask the service that owns the figure" rule, commented
   as such — nothing owns it any more, and the path contract fixed `MealPlanService` at
   "remove the endpoint and its method only".
4. **The handover pill on the meal's own card** (`MealServices.tsx`, new `HandoverBadge`):
   `<Badge tone="info">` reading exactly "We deliver it" or "They collect it", only on an outside
   meal that has a handover. **Both readings are blue.** Rajeev chose blue in the terminal, and the
   work manager settled that both wear it: amber is reserved for something to act on, these meals
   already carry the amber loading-time warning, and colour in this product means severity and never
   category (DESIGN_SYSTEM v1.14) — two colours would say one handover mattered more than the other.
5. **Today's cross-date heads-up** — a `GoingOutCard` in the narrow column under Deliveries, each row
   `Sat 26 Sept · <event name>` with the same blue pill, linking to `/planner?date=…`; nothing drawn
   at all when the list is empty.
6. **Today's dead planner links gated** on `plannerRefused(appUser)` (the menu's own
   `whoami.canPlanMeals` test): the header's Open planner, the catch-up nudge's Record them, the
   fasting notice's Review menu, the empty state's Open planner, the Servings-today and
   Cost-of-materials tiles' hrefs, and the meal rows (drawn through a new `MealRow` that is a link or
   plain text). The facts stay; only the acts go.
7. **`frontend/app/kitchens/page.tsx`** heading "Kitchens" → "All kitchens", to agree with the menu.
8. **`frontend/components/ds/PeriodNav.tsx:36`** comment "issued from store" → "issued to kitchens".
