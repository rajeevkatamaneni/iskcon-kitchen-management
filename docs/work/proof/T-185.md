## What was copied from T-169b, and from where

All of it is from `frontend/app/settings/page.tsx`, and it is copied into the component, not imported. Those pieces are private to the page, and a component shouldn't reach into the screen that mounts it. The comment in the component says a third copy is the moment to move them to `components/ds`.

- **`useEditMode`** (page lines 207–227): copied line for line. Edit takes a snapshot, Cancel restores it and closes, and closing remounts the `Form` through `formKey`.
- **`EditActions`** (page lines 243–305): the same buttons, words and classes:
  - Edit: `btn btn-quiet … px-6`
  - Cancel: `btn btn-quiet … px-5`, placed before Save
  - Save: `btn btn-primary … px-6`, `type="submit" form="language-form"`, reads "Saving…" while in flight
  
  I left out the two props only other sections use (`saveLabel`/`savingLabel` for Connect, `saveDisabled` for "nothing changed"). So Save is greyed out only while saving.
- **The shared `Form`** (`@/components/ds/Form`): it wraps the picker as it does on Email, with `key={edit.formKey}`, `id="language-form"`, and `onSubmit` that saves only while editing.
- **The Save flow:** Email's. Edit clears "Saved.", a successful Save shows `<p className="mt-6 text-sm text-success">Saved.</p>` and closes the section, and a failure shows the same `role="alert"` block and stays open.
- **`required` is left off.** The select always holds one of the 23 languages and can never be blank, so `required` would change nothing.

**One choice of mine: the snapshot is `picked`, not the shown language.** `picked` is null until someone chooses, and the shown value is derived from the prop (the T-077 fix). If Cancel pinned the shown value, a temple language arriving after a cancelled Edit would never show, which is T-077 again. The test "still reads a language that arrives later, after an Edit that was cancelled" pins this.

## Read-only styling

A `<select>` has no read-only state, so it is `disabled={!edit.editing}` with `disabled:bg-sunken`. That is exactly how the payment gateway's provider select does it (page line 460). The chosen language stays visible.

Seven new tests are in `settings-language.test.tsx`, under "the temple's language opens read-only":
- It opens with the language shown, the picker disabled with the sunken fill, Edit enabled, and no Save or Cancel.
- Edit opens the picker, with Cancel before Save and the quiet and primary classes, and Edit is gone.
- Save sends `setTempleLanguage("hi", token)` once, shows "Saved.", and closes the picker. It is still once after the async queue settles.
- Cancel puts back the language from before Edit, and so does a second Edit. Nothing is sent.
- Cancel after an earlier save puts back that saved choice, not the opening language.
- A language arriving after a cancelled Edit is still read.
- Save is enabled straight after Edit, and disabled (reading "Saving…", with Cancel disabled too) only while in flight.
