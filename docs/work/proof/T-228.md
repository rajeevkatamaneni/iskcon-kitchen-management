## How it works

Wide (1024px and up): primary flexible column `width: 40%`, secondary `15%`, flexible cells wrap
(`overflow-wrap: anywhere`, never ellipsis). Fixed cells are right-aligned, `nowrap`, `width: 1px`
(shrink to content). The first fixed column is left at `width: auto`, so the auto table hands it the
spare width; because it reads right, the spare room shows between the last flexible column and the
fixed group. Padding: 20px at both row ends, 12px either side of every other cell.

Below 1024px: thead hidden visually (kept for screen readers), each row a flex card. Line 1 is the
flexible cells; a zero-height full-width `::after` breaks the line; line 2 is the fixed cells, with the
actions cell pushed to the far edge. A fixed cell that would be a bare number carries `data-label`,
printed before the value ("On hand 12 kg"). Empty cells are hidden.

## Acceptance criteria

1. Even edge padding — 20px both ends, measured on /ingredients.
2. Every column classified — table above; unclassifiable ones listed below and left alone.
3. Flexible left, fixed right and snug — `table-rule.test.ts` fails if a flexible heading follows a
   fixed one in any ruled table; widths measured in the browser.
4. Caps 40% / 15%, wrap not truncate — CSS asserted in the test; measured (Name 450/1124, Category 169).
5. Spare width after the caps sits between the groups — measured (Unit took 253px, right-aligned).
6. Numbers right-aligned with tabular numerals, headers aligned like columns — `TD_FIXED_NUM`, header
   classes match their cells.
7. Actions header visually removed, sr-only kept — test asserts every `TH_ACTIONS_FIXED` holds only an
   sr-only span; jsdom tests reading header text still see "Actions".
8. Cards below 1024px, no horizontal page scroll — measured at 390 and 768.

**Judgement calls made, worth a glance:**
- The breakpoint is `lg` (1024px) for every table, including small two-column ones that would fit at 768.
- Log-style tables (movements, equipment audit trail, donations) now have the date on the right, as the rule says.
- Long email addresses now break mid-address at the 15% cap on /users. The rule says wrap, never truncate; if that looks wrong, the fix is to class Email as primary or let it break at the "@" only.
- Card layout drops table semantics in some browsers (Safari) once rows are `display: flex`; the header row is still in the DOM for screen readers. Not tested with a screen reader.
