# T-214 — Today names an event meal by its own name, not "Event"

Defect 2 of `docs/work/proof/phase-A-browser.md`. Today now calls a meal `eventName` when it has one
and `mealKind` otherwise, which is the rule `derivedTitle` in `ShiftLayer.tsx` already follows (that
file was read and not edited).

**Files changed:** both are inside the contract.
- `frontend/app/today/page.tsx`: new `mealName(meal)` helper (`eventName || mealKind`, `||` as in
  `derivedTitle`). It is used at every place the page names a meal: the "Servings today" note, the
  meal row `aria-label`, the meal row heading, and the "Working today" crew line. `grep -n mealKind`
  on the page before the change found exactly those four renders. `WorkforceNote` now also takes
  `meals`.
- `frontend/__tests__/today.test.tsx`: new `describe` block with 6 tests.

**Server check:** the server does populate `eventName` for Today.
`backend/src/main/java/org/iskcon/kms/today/TodayService.java` `mealsOf` passes `meal.eventName()`
into `TodayView.Meal`. No backend or `api.ts` change was needed.

**One design point to know about.** The crew line is drawn from `workforce.meals`
(`MealCrewView`), and that type has no `eventName`, neither on the client nor in the backend record
`MealCrewView.java`. Both belong to T-215 this wave, so the page looks the name up by `mealId` in
`data.meals` (the type's own comment says "Match on this, never on the kind's name"). A crew row whose
meal is not in today's list falls back to its kind. This happens when every dish of the meal was
cancelled, because `mealsOf` then filters the meal out.
