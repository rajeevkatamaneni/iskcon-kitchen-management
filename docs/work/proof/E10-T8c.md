# E10-T8c — every stock item gets one stored Kannada name; the assistant uses it and never makes its own

Main checkout, branch `agentic-mvp`. Nothing committed, pushed or deployed. Backend and prompt only;
no frontend.

## Files changed (all inside the task)

- `backend/src/main/resources/db/migration/V161__glossary_knows_machine_names.sql`: new. V161 was free
  (the highest before it was V160). Adds `machine_translated_at TIMESTAMPTZ` and `machine_provider TEXT`
  to `translation_glossary`, with a CHECK that they are both set or both null. No backfill: every row that
  exists was typed by a person, which NULL already says. The table keeps its V13 RLS policy. It is not
  append-only (people edit and delete entries), so nothing about that applies.
- `backend/src/main/java/org/iskcon/kms/translation/StockNameFillService.java`: new. `fillStockNames(language)`
  finds the temple's stock items (`inventory_items` joined to `ingredients`) with no glossary entry in that
  language, compared case-insensitively the way the unique index compares. It translates the read-aloud
  form (`Translatable.ingredientName(...).forMachine()`) in batches of 100, and inserts each with
  `ON CONFLICT DO NOTHING`, marked with `now()` and the provider name. It never updates a row, and a
  second run finds nothing missing and calls no translator. Everything runs on the caller's connection
  under RLS; the tenant comes from the session setting, as `GlossaryService.upsert` does.
- `backend/src/main/java/org/iskcon/kms/translation/GlossaryController.java`: `POST
  /api/v1/translation-glossary/fill-stock-names`, Kannada only, behind `MANAGE_RECIPES` (the permission
  the glossary uses for adding an entry). Returns `{language, stockItems, added, provider}`.
- `backend/src/main/java/org/iskcon/kms/translation/GlossaryService.java`: `upsert` (the person's path)
  now clears both machine columns when it updates a row, so a corrected name stops being "unchecked".
- `backend/src/main/java/org/iskcon/kms/assistant/mcp/InventoryTools.java`: class comment only. The tools
  already read the whole glossary through `GlossaryService.lookup`, so machine rows come through as
  `name_kn` with no code change. No translation and no write inside a tool.
- `backend/src/main/java/org/iskcon/kms/assistant/mcp/McpServerConfiguration.java`: tool descriptions.
  `name_kn` is now "use it exactly as given; when absent give the English name only and never translate
  the name yourself". The old text ("translate if you must and say it is yours") is gone.
- `backend/src/test/java/org/iskcon/kms/translation/StockNameFillIT.java`: new, 6 tests.
- `tools/assistant-dev/kitchen-assistant.md`: the item names in a reply come from `name_kn`, letter for
  letter, with English in brackets the first time; English only when there is no `name_kn`; never
  translate, respell or shorten a name. **The word list is kept**, but as a search aid only. It is how a
  Kannada question finds the English store item (ತುಪ್ಪ → ghee). The glossary's machine spelling may not
  match what a cook types (Google gives ಮುರಿದ ಅಕ್ಕಿ where people say ನುಚ್ಚಕ್ಕಿ), so it is still needed for
  input. It now says it is for searching only and is not to be used when answering.
- `docs/work/proof/E10-T8c.md`: this file.

Not audited: no glossary change is audited today (add, correct and delete write no audit entry), so the
fill follows that. Who wrote a machine row is recorded on the row itself.

`GlossaryEntryView` (what `GET /translation-glossary` returns) was **not** changed, so the screen cannot
show the mark yet. That belongs with the glossary-screen button, along with `api.ts`.

## Which translator is active locally

`TRANSLATION_PROVIDER=stub` in `tools/local-backend.sh`, so a fill on the local stack as it starts today
writes `[kn] Mace`, which is junk (marked `machine_provider = 'stub'`, so it can be told apart and deleted).

**Google can run locally with no secret and no login.** This Mac already has application-default
credentials (`~/.config/gcloud/application_default_credentials.json`, quota project `iskcon-kms-2026`).

`TRANSLATION_PROVIDER=google GCP_PROJECT_ID=iskcon-kms-2026` in place of the stub setting.

## Acceptance criteria

- **V161 marks machine rows, with the time:** two columns plus the both-or-neither CHECK. Flyway applied
  it in the run above. RowLevelSecurityIT is green.
- **Fills only the missing:** "names only the stock items…". Of three stock items, the one a person had
  named ("ghee" in lower case against "Ghee") is skipped. An ingredient that is not stock is not named.
- **Read-aloud name sent:** "Rice, broken" is stored as `[kn] Broken rice` under the key `Rice, broken`.
- **Never overwrites:** the person's row stays the same and unmarked. A machine row's timestamp does not
  change on a later fill.
- **Safe to run twice:** the second run returns `added: 0` and the glossary is identical.
- **Tenant-scoped under RLS:** temple B's own name for an item does not stop temple A's fill, and B gets
  nothing from A. B's own fill names only B's missing item. Checked through the privileged connection,
  which sees both temples.
- **Permission:** a Volunteer gets 403 and nothing is written.
- **A person's correction clears the mark:** in the "never overwrites…" test.
- **The tools return machine names as `name_kn`:** `get_inventory` and `list_low_stock` return the
  person's ತುಪ್ಪ and the two machine names. The glossary still has three rows afterwards, so the tools
  wrote nothing.
- **Prompt updated:** see the files list.
