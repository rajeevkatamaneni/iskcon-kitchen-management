## What PriceTrend.tsx does, checked against the rule

It matches the rule. `priceDirection` returns null when either the current or the previous price is missing, and `PriceTrend` then renders nothing. A difference under 0.00005 counts as "same". `LOOK` maps `up` to `ti-arrow-up` + `text-danger` (red), `down` to `ti-arrow-down` + `text-success` (green), and `same` to `ti-minus` + `text-ink-secondary` (the neutral dash). The arrow's spoken name says the direction in words ("Up from ₹60 on 12 Sept"), so colour is not the only signal. `__tests__/price-trend.test.tsx` passes (15 tests, output below).

## DESIGN_SYSTEM v1.14 — 2026-09-19

**Price-trend arrows written in as the one exception to the colour rule, and the layout rules made a

**Why.** The procurement requirement for vendor price history (R-VEN-3) puts an arrow beside each
list price: red up when the price rose, green down when it fell. Under the v1.10 colour rule, red is
only for something serious and green only for the reader's own action succeeding, so a green arrow
for a price the reader did nothing to lower broke the rule. The requirement called it an approved
exception but asked for his confirmation and for it to be written down.

**What changed in the document.** §2, *Semantic, status only*, gains *The one exception: price-trend
arrows*: red up arrow for a rise, green down arrow for a fall, the neutral dash when unchanged, and
nothing when there is no previous price. It holds for price trends only; nowhere else may use red or
green for a direction, a trend or a comparison. §5, *Layout*, opens with a line covering the whole
section, *Tables* included: its rules state intent, and when one can't be met literally, follow its
logic (readable, nothing hidden, no dead space) and take the closest, lesser-evil result. Before this,
builders read the table rule word for word even where the result was worse.

**The code already followed the arrow rule.** `components/PriceTrend.tsx` was built this way. Its comment now
records the decision (T-283, `docs/work/proof/T-283.md`). No behaviour changed.

**Nothing else in the file changed**: the status line, §2 and the head of §5 only. Snapshot in
`docs/versions/DESIGN_SYSTEM_v1.14.md`.
