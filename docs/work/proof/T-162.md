## Tests changed, and why

Three existing tests asserted a hand-written "date already passed" message. `Form` now refuses the
date first, using the box's own `min`, so that message never shows. In a real browser it never
showed before either, because the browser blocked the submit on the same `min`. Each test now presses
Save or Raise order and asserts `Form`'s sentence, and still asserts that nothing is sent. Each
carries a "CHANGED AT T-162" comment.
- `manual-purchase-order`, "refuses a needed-by date that has already passed": the assertion is now "Needed by must be on or after <today>".
- `order-detail`, "refuses a date behind the order itself": now "Needed by must be on or after 1 Aug 2026". The old text was "before the order was raised".
- `shopping-list`, "refuses a date that has already gone": now "Needed by must be on or after <today>", inside the panel.

No other existing test changed. The other `fireEvent.submit` calls still pass. `Form` checks the
boxes on any submit, and those tests submit valid forms.

## Hand-written checks that duplicate a rule on the box

None of them shows a second message beside `Form`'s, because `Form` stops the submit before the
page's handler runs. I left all of them in place.
- `orders/new`, `choose`: `if (vendorId === "") return;` repeats `required`. It is now unreachable.
- `orders/new/lines`, `raise`: "That date has already passed" repeats the date's `min`, and is now unreachable. The quantity-above-zero check overlaps `min="0"`: a negative is now `Form`'s, while 0 and blank are still the page's.
- `PurchaseOrderEditor`, `save`: the "before the order was raised" date check repeats `min`, and is now unreachable. Its quantity check overlaps in the same way.
- Order, `receive`: the price-below-zero check overlaps the price's `min`. Order, `submitReturn`: quantity at or below zero overlaps `min`.
- Invoice dialogs: `ready` (reason not blank, amount not blank) and `written === ""` repeat `required` as a disabled button. `credit > 0` is stricter than `min="0"`.

## Labels that make a poor name

- **The invoice dialogs are the bad ones.** Each `<label>` holds the question and its hint. `Form` reads the whole label, and the two spans run together with no space. What renders:
  - "How much is being credited?In rupees. It cannot take what is owed below what has already been paid. is required"
  - "What is the credit for?Kept with your name and today’s date, and never overwritten. Whoever argues this with the vendor next year reads it. is required"
  - "Why was this bill never owed?Kept with your name … reads it. is required"
  - "What happened?A bounced cheque, a mistyped amount, a payment against the wrong bill. It is kept with your name and today’s date. is required"

  There are two causes. The hint sits inside the label, which is the page's markup. And `Form` joins
  the label's text without spaces, which is `Form.tsx` and not mine to touch. Hidden today behind the
  disabled buttons.
- "Why is required", on the close form.
- "Price paid per Kg of Rice, optional can have at most 2 decimal places". The ", optional" is part of the aria-label.
- "Note about the return, optional can have at most 1000 characters". This is unreachable by typing, because `maxLength` stops the typing.
- "Date is required", on the payment row. It is vague, but it sits beside the box.
