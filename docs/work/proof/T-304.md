# T-304: nothing runs past its box, a long pasted token breaks inside its cell, and a refusal is brought into view and focused

## Files changed (all inside the contract)

- `frontend/components/ds/table.ts`
  - `fitTable` now runs the old fit (renamed `fitOnce`, which returns how many pixels the table still runs over). If that number is above 0, it tries three more steps in order, re-measuring the real table after each one:
    1. Close the gaps between columns evenly, only as far as needed and never below 6px a side. This step is tried only if closing every gap to 6px would cover the shortfall.
    2. Break long tokens after `@ . - / _`, closing the gaps as well if that is still needed.
    3. Break long tokens anywhere.
  - New constants `CELL_PAD = 12`, `CELL_PAD_MIN = 6` and `LONG_TOKEN = 21`. A token only counts as long at 21 characters or more, so a PO number (12 characters) never breaks.
  - New export `withLongTokenBreaks`. It takes out the word joiner inside a long token so its hyphens can break.
- `frontend/app/globals.css`: the inner cell padding is now `var(--kms-cell-pad, 12px)` on `.kms-table` and `.kms-entry-grid`, from 1024 up. The 20px at each end of a row is unchanged.
- `frontend/components/PurchaseOrderEditor.tsx` (the PO editor, used by the order page and the shopping-list panel)
  - New export `revealNotice`.
  - A refusal from the form, or a failed save, now scrolls the host's notice (`role="alert"`) to the centre of the screen and focuses it (`tabindex="-1"`).
  - In the panel it looks inside the dialog only. It stops if the form closed, because the save succeeded.
- `frontend/app/orders/new/page.tsx`: shows each new refusal or failure the same way, using `revealNotice`.
- `frontend/app/invoices/[id]/page.tsx`: in `Detail`, the wrapper is `min-w-0` and the value is `[overflow-wrap:anywhere]`. A plain-text value also gets `withLongTokenBreaks(…, "separators")`.
- `frontend/__tests__/table-rule.test.ts`: the two CSS assertions are updated for the variable, and there are 5 new tests.
- `frontend/__tests__/refusal-in-view.test.tsx`: new, 5 tests.
- `frontend/__tests__/po-create-form.test.tsx`: 2 new tests.
- `frontend/__tests__/invoice-detail.test.tsx`: 1 new test.
- `docs/work/proof/T-304.md`: this file.

`app/shopping-list/page.tsx` was not changed. Defect 1 is fixed centrally, in the fitter.

## Defect 3: why scroll and focus, not a notice beside Save

Putting the notice beside Save only fixes the refusals the form makes itself. Two cases would still be missed:

- A server refusal on the same press, such as KMS-400050 or a line the server names. The host draws these at the top of the page, with the field errors.
- `/orders/new`. Its Create order button is in the sticky header, so there is no Save at the foot to put the notice beside.

Scroll and focus covers every refusal on all three screens with one behaviour, and it needs no change to `orders/[id]/page.tsx`, which is outside my contract. Focus also makes a screen reader read the refusal out. The notice is scrolled to the centre of the screen, not the top, so the sticky header never covers it.

## Acceptance criteria

1. **"No vendor yet" overflows 0px at 1024.** Met; measured above. No word is broken; the gaps went from 24px to 20px.
2. **A token over ~35 characters never widens the page at 1024 or wider; it breaks at `@ . - /` first, anywhere as the last resort.** Met; measured above.
   - Fixed centrally in `table.ts` and `globals.css`, plus the invoice page's `Detail`.
   - PO numbers and names under 21 characters are never broken (unit test).
3. **A failed save's error is visible on a phone.** Met: it is scrolled into view and focused, with the position measured above and unit tests on both paths.

## Not done / needs Rajeev

- **A deviation from §5 rule 4 (12px either side of a cell), taken by Q-18's lesser-evil logic.** When a table would otherwise run past its box, the gaps close up, never below 6px a side. The alternative was to break a word or code mid-way.
  - It only triggers on tables that could not fit before. With no injection, that is only "No vendor yet" at 1024, which gets 10px a side.
  - He may prefer a different floor.
- **The order in which a long token is handled.** The fitter closes gaps before it breaks a pasted token. So at 1280, a 60-character token sometimes stays on one line with 7px gaps, rather than breaking. That is a judgement call for him.
- **Focus styling.** A focused notice shows the browser's focus ring only when the last input was from the keyboard. I did not restyle `ErrorNotice`, because it is outside my contract.
- **The API was down for about 10 minutes mid-task.** I did not restart it; it came back on its own.
- **No hand smoke test in Rajeev's Chrome.** Everything was driven in headless Chromium.
