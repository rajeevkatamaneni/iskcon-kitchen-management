## Decisions recorded

- **Duplicate (KMS-400157): translated only, no pre-check.** SQLSTATE 23505 on the insert becomes `PACK_SIZE_ALREADY_THERE`. The unique index is the rule, and a pre-check would only restate it.
- **Same family (KMS-400013): both.** First `IngredientUnits.requireSameFamily`, which names the ingredient ("Rice is measured in Kg, and there is no way to turn L into Kg."). Then the trigger's 23514 (`ingredient_pack_sizes_same_family`) is translated to the same code.
- **At most 8 (KMS-400158): counted in the service after `SELECT … FROM ingredients WHERE id = ? FOR UPDATE`.** The row lock makes the count reliable when two people save at once. `IngredientService.update` takes the same lock before counting packs on a family change.
- **In use (KMS-400159): translated.** SQLSTATE 23503 on the DELETE becomes `PACK_SIZE_IN_USE`. This covers `vendor_supplies` and also `vendor_invoice_lines` (both RESTRICT). The code's wording talks about a vendor, which fits an invoice line only loosely.
- **Family change (KMS-400160):** `update` refuses only when the family changes and packs exist. Kg→gm is allowed.
- **Audit:** no pack-size audit action exists or was reserved, and `AuditAction.java` is outside the contract. So each add and remove is an `INGREDIENT_UPDATED` on the ingredient, with before and after `{name, packSizes:[labels]}` and a reason such as "Added pack size Bag = 25 Kg."
- **Label:** `Quantities.exact` in readable units (clarifier: settled by §1), with "Name = " in front when the pack has a name. The conductor's ruling: the document's "250 g" is read as the app's existing gram label, per §1, so chips read "250 gm · 500 gm · 1 Kg · Bag = 25 Kg". "Pack = 0.5 Kg" reads "Pack = 500 gm".
- **`baseQuantity`** is in the ingredient's canonical unit, as api.ts says, using `InventoryUnits.fromBase`. This is not V144's `base_quantity`, which is in grams. Example: a 500 gm pack on a Kg ingredient is 0.5.
- **The list** loads every pack in one query (`PackSizeService.allByIngredient`), not one per row.

## Acceptance criteria

- **Sizes persist:** `sizesPersistAndReadBack` adds 4 packs, reads them back smallest first with labels and `baseQuantity`, counts the rows as the admin role, and checks 4 audit entries and their reason text.
- **Positive:** `quantityMustBePositive` covers 0, -5, a missing quantity and an unknown unit. The first three give KMS-400001 with the field message, and nothing is written.
- **Same family:** `sameFamilyOnly` refuses L and PIECES on a Kg ingredient with KMS-400013, and accepts Kg on a gm ingredient.
- **No duplicate:** `duplicateSizeIsRefused` refuses both 500 gm then "Pack = 0.5 Kg" and 500 gm twice with KMS-400157. One row and one audit entry remain. `duplicateIsPerIngredient` checks the rule is per ingredient.
- **At most 8:** `atMostEight` refuses the 9th with KMS-400158. Removing one makes room again.
- **Removal refused while a supply uses the pack:** `removalRefusedWhileInUse` gets KMS-400159 while `vendor_supplies.pack_size_id` points at the pack. After the supply is cleared, the delete works.
- **Family change refused while packs exist:** `familyChangeRefusedWhilePacksExist` refuses KG→L and KG→PIECES with KMS-400160, allows KG→GM (the bag still reads "Bag = 25 Kg", baseQuantity 25000), and allows KG→L once the packs are gone.
- **RLS:** `anotherTempleCannotReachThem` signs in as temple B's staff. GET, POST and DELETE on temple A's rice all return 404, and B's list shows only B's own "Sack = 50 Kg". A's list does not contain B's pack.
- **The list returns packs and market rate:** `IngredientIT.listCarriesPackSizesAndMarketRate` checks `marketRate` 60.5, `marketRateOn` "2026-09-12", `marketRateSource`, and packs on the list. An ingredient without them returns an empty array and nulls. The detail endpoint returns the same.
- **Permission:** `volunteerIsRefused` returns 403 for a user without `MANAGE_RECIPES`.
