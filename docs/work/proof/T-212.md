## The rule, as built

- A meal whose `meals.recorded_at` is set is costed at each dish's `actual_servings`. Any other meal is costed at each dish's `target_yield`. Cancelled dishes stay out, which includes "not made", since recording sets those to CANCELLED.
- The switch is the meal's recording, not a dish's status. Recording sets `recorded_at` in the same transaction that writes `actual_servings` on every dish it cooks, and it refuses a dish without one. The V137 reseed also writes `actual_servings` on every recorded dish (checked).
- Head counts, which divide the cost into a per-serving figure, still come from the meal row, unchanged.
