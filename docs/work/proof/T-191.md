# T-191 — correct the uid-escape Javadoc, remove UserRepository.findByFirebaseUid, fix two false texts in build.gradle.kts

**Files changed:** all inside the contract.

- `backend/src/main/java/org/iskcon/kms/tenancy/TenantContext.java`: Javadoc on `setAuthLookupUid` only.
- `backend/src/main/java/org/iskcon/kms/user/UserRepository.java`: `findByFirebaseUid` removed, its unused `Optional` import removed, and `findAllByFirebaseUid`'s Javadoc rewritten to carry the reasoning.
- `backend/src/test/java/org/iskcon/kms/notification/WhatsAppTestSendIT.java`, `WhatsAppTemplateSubmissionIT.java`, `WhatsAppTemplateComparisonIT.java`, `WhatsAppTemplateReloadIT.java`: lookup line only. Now `findAllByFirebaseUid(uid)` filtered to `govinda`, the temple the fixture puts that person in.
- `backend/src/test/java/org/iskcon/kms/inventory/StockMovementLedgerIT.java` (both sites): `users.findById(actorA)`, the id the fixture already holds for `uid-admin-a`.
- `backend/src/test/java/org/iskcon/kms/ops/TemplateStatusCopyIT.java`, `TemplateStatusCountsIT.java`: lookup lines in `signInAs`. There is no temple to filter by, because the operator has none and the context is cleared inside the helper. So it takes `findAllByFirebaseUid` and asserts the uid holds exactly one account. A fixture that ever gives that uid a second temple fails loudly instead of picking one.
- `backend/src/test/java/org/iskcon/kms/tenancy/RowLevelSecurityIT.java`: a pointer added to the Javadoc of the own-uid visibility case. It says V2's comment predates V52 and names where the current account lives.
- `backend/src/test/java/org/iskcon/kms/tenancy/OwnAccountsAtOtherTemplesIT.java`: one new test, plus the `Method` and `Arrays` imports.
- `backend/build.gradle.kts`: comment and message text only.
- `docs/work/proof/T-191.md`: this file.

Nothing under `db/migration/` or `frontend/` was touched. (`git diff --stat` also lists `frontend/` files and `docs/work/DISPATCH.md`. Those belong to T-194 and the work manager.)

**V2 was deliberately left alone.** Its comment says the escape "exposes exactly one row", which has been false since V52. But Flyway checksums applied migrations, so editing that file would stop staging from starting. The correction lives on `TenantContext.setAuthLookupUid`, and the own-uid case in `RowLevelSecurityIT` points to it.

**Choice for item 3: (a), remove it.** The method had no caller in main code, and the test changes were one or two lines each. A main-code method used only by tests is where the next caller finds it, and for anyone with two temples it throws. Filtering `findAllByFirebaseUid` by temple says in each test which account it means.
