## Acceptance criteria

**"A correction posted from the UI produces a reversing `ADJUSTMENT` cross-referenced to the
original, and the history shows both."**
Each history row gains a "Correct" action, which opens a dialog taking the mandatory note
(`required`, `maxLength={500}`) and calls `api.compensateMovement(id, note, token)`. On success the
history and the item header both re-read, so the reversal appears in place and the on-hand figure
above it moves with it. The two rows are linked in both directions off the one list the screen
already has, using `referenceType === "CORRECTION"` and `referenceId`: the reversal reads
*"Correction of the cooked on 1 Sep 2026 09:30"* and the original is tagged *"Corrected"* — no
second request, and no hex id shown to a reader. Verified by test 1, which asserts the exact call
`("mv-1", "Counted the wrong batch", "test-token")`, then that both `-2 Kg` and `+2 Kg` are on
screen with the original still present and marked.

**"Correcting an already-corrected movement surfaces the server's refusal as readable text — not a
silent failure and not a raw code dump. Branch on the KMS code from `ApiError.code`, not on the HTTP
status number."**
Branches on `ALREADY_CORRECTED = "KMS-400039"`, a named constant with the reason in a comment. No
status number is read anywhere in the file. The dialog turns into the server's own sentence and its
own next step, rendered as prose with the code kept quiet and monospaced the way `ErrorNotice` has
it — and because that next step says *"look at the correction that was already recorded"*, the
history behind the dialog is reloaded so the correction is actually there to look at. Verified by
test 2, which asserts the message, the action, the visible `KMS-400039`, that no `409` reaches the
reader, and that the control was **not** hidden afterwards.

Note on the code: `MOVEMENT_ALREADY_CORRECTED` is `400039` in `ErrorCode.java:245`, i.e. post-
renumber. `docs/ERROR-CODE-RENUMBER-2026-09-07.md` (signed off 2026-09-07) moved it from the old
`KMS-4908`, and every other `KMS-` literal in `frontend/` is already six-digit, so this matches the
tree. **My task brief did not mention the renumber**; flagging it in case other tasks this wave were
briefed with four-digit codes.

**"Deleting an item returns to the inventory list and the item is gone. A test asserts the
confirmation copy states the ledger survives."**
"Stop tracking this item" sits at the foot of the screen under a rule, away from the daily stock
controls. Its confirmation states both halves explicitly: it comes off the inventory list and out of
low-stock warnings, and *"Every movement stays in the ledger. Nothing that was received, donated,
cooked or written off is erased."* On success it calls `api.deleteInventoryItem(id, token)` and
`router.push("/inventory")`. Test 3 asserts each of those copy lines, the delete call, the push, and
— the point of the warning in the task — that `adjustStock` was **never** called, so no false
zeroing event is written. Test 4 asserts Cancel deletes nothing.

## Two things worth a second look

**A pre-existing rendering defect, fixed because it was inside the feature and inside the contract.**
The reason/note cell printed the reason and the word "Correction" as adjacent expressions with no
separator. A correction always carries `COUNT_CORRECTION`, so every correction row already in the
ledger rendered as the single run-together word **"Count correctionCorrection"**. It now prints one
or the other, and for a correction it prints what the row reverses. This was on the line the task
described as "already labels corrections"; it labelled them, but not legibly.

**The control is deliberately offered on rows the screen can already see a correction against.**
The task said to surface the refusal rather than hide the control, so I did not hide it. This is
also right on its own terms — two people on two tabs is ordinary in a store, and the second presser
is looking at a screen that was correct when it loaded — but it does mean the "Corrected" tag and
an enabled "Correct" button appear on the same row. That is a deliberate deviation from what a
reader might expect, and reversible in one line if Rajeev would rather the tagged rows were inert.
