## The rule, and why

After the controls are taken out of the label copy (as before), any element inside the label whose
**own** classes include `text-ink-secondary`, `text-ink-muted` or `text-danger` is taken out too.
What is left is the name. If nothing is left, the label's whole text is used, as T-160 did.

Why these three: `text-ink-secondary` is `FIELD_HINT`'s colour and is on every grey sentence under a
question. `text-ink-muted` is on `Field`'s "(required)" and on the grey half of tick-box lines.
`text-danger` is `FIELD_ERROR`'s colour and is on the kitchen's inline duplicate-name error. Every
question span in every label is `text-ink` or has no colour.

Why not the other options:
- "Text before the box" fails every tick-box and radio. Their words come after the box, and several
  have a grey note after the words too (meal kinds, occasions, closing an order).
- `aria-describedby` or roles: no hint inside any label carries an id or a role. The only hint in
  these forms that uses `aria-describedby` (closing an order, "close-note-hint") sits outside its
  label on purpose. A clause for it would guard a case that does not exist.
- Only the element's own classes count, not the label's. Most labels are `text-ink-secondary`
  themselves, and a tick-box with its words straight in the label ("Preferred", "Direct, with no
  purchase order") would otherwise lose its name.
- I did not add a space between spans. Once the hint is gone nothing is left to glue, and a space
  between text nodes breaks JSX like `({unit})`.

## Sweep of every label inside a Form

Method: `scratchpad/sweep-T-171.mjs` pulled every `<label>…</label>` from the 23 files that import
`Form` (127 labels). I also checked the child components those files import that contain `<label>`:
`DateRange` (two plain question spans), `Field` (`htmlFor` label, "(required)" span is
`text-ink-muted`), `PurchaseOrderEditor` and `VendorStatusDialog` (both already in the 127).
`InfoHint`'s `<label>` matches are in comments plus one `htmlFor` label outside any wrapped box.
No `htmlFor` label is written by hand in the 23 files.

What the rule gives, by shape:
- Question span, then box (about 100 labels): the question. Unchanged from T-160.
- Question span, box, grey hint span: the question. Record a service, Void a gift, the vendor
  status reason (both wordings), four invoice boxes, and invoices/new "Purchase order" when its
  "no open orders" note shows. All fixed.
- Question span, box, red error span: the question. Kitchen name. Fixed.
- Box then plain words (Anonymous donor, Preferred ×2, Direct, with no purchase order): the words.
- Box then `<span>` words (This never needs servicing ×2, Ekadashi-prohibited, This kitchen plans
  its meals here): the words.
- Box then words plus a grey note (meal kinds ×2, occasions ×2, close-outcome radios, Vendor Never
  Delivered): the words alone. These were poor under T-160 ("…a feast it must name the festival…").
- "Arrived" tick per order line: the ingredient's name, without the grey quantity.
- Labels whose box has an `aria-label` (Cash amount, Towards, How often, Interval unit): the
  `aria-label`, unchanged.

Still poor, one label: **"This is the temple’s main kitchen"** (`components/KitchenForm.tsx:287`).
Its explanation spans are `mt-1 block` with no colour of their own, so the name would read
"This is the temple’s main kitchenA temple’s only kitchen is its main one, so this one is." It can
never be shown: the tick-box is not `required` and has no other check. Fixing it means giving those
spans `text-ink-secondary`, a page edit outside this contract.

Borderline, not wrong: "Anything to add? (optional)" (vendor bring-back) keeps "(optional)", but that
box is only required when dropping, and then its wording is "Why are they being dropped?".
"Note (required for “Other”)" keeps its bracket; it is not `required`.

## Not done / follow-ups

- **No hand smoke test in a real browser.** Staging is off limits and memory is tight, so I did not
  run the app. The rendered names are proved in jsdom only.
- `KitchenForm.tsx:287`, the main-kitchen tick: its explanation spans have no colour class, so its

  written in `text-ink-secondary`, would break it silently. A test in `design-system.test.ts` could
  check that no label's question span uses those classes. That file is outside this contract.
- `eslint.config.mjs` does not lint `components/`, so `Form.tsx` itself is not linted by anyone. That
  is by design, and I'm only noting it.
