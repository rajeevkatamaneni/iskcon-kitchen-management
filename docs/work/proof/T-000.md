### Deliberately not touched, and why

- **`docs/work/`** — the work machine's own state, as instructed. Untouched entirely, including the
  proposed codes in `INTAKE.md` and `DISPATCH.md`.
- **`docs/CHANGELOG.md`** (4 mentions) and **`docs/WORK_QUEUE.md`** (3 mentions) — release agent's
  files. See "For the release agent" at the bottom.
- **`.claude/agents/work-manager.md`** (uses `KMS-4936` as a collision example) and **`CLAUDE.md`**
  (says `KMS-nnnn`) — harness configuration, not a builder's to edit. Both need a one-line update;
  flagged below.
- **`backend/src/main/resources/db/migration/`** — **11 comments and one `COMMENT ON` string across
  7 applied migrations still quote four-digit codes, and I left them.** Editing an applied migration
  changes its Flyway checksum and the application then refuses to boot against any database that
  already ran it, staging included. The tree already sets this precedent explicitly — V67:
  *"the comment cannot be edited in place — V22 is applied, and rewriting an applied migration
  breaks its checksum"* — and `EPIC-4` says the same of applied migrations as historical record.
  The one that reaches a live database is the comment on `employment_ban_raising_tenant(uuid)` in
  V65, naming `KMS-4307` (now `KMS-400027`). **Judgement call, flagged for Rajeev**: correcting it
  needs a migration of its own, the way V67 restated V22's.
- **`KMS-0000`** (23 mentions across `frontend/lib/api.ts`, `document-download.ts` and 6 tests) —
  the frontend's sentinel for *"the server gave us no code at all"*. It is not an `ErrorCode`, so it
  had no number to renumber, and inventing one would be taking a code I was not allocated. It is now
  the only four-digit reference the app can put on a screen. **Flagged for Rajeev.**
- **Four numbers with no successor**, left four-digit and marked "old-scheme" in the docs that name
  them: `KMS-4017` (`SERVICE_PROVIDER_IN_USE`, reversed by V90 before deploy), `KMS-4927`
  (`USER_NOT_KITCHEN_STAFF`, shipped then retired), `KMS-4969` and `KMS-4972` (proposed in the Epic 2
  library design, never built).

### 3. The sweep itself, and the audits over it

The mapping was generated from `ErrorCode.java` by parsing its declarations, and every rewrite came
from that map — no reference was hand-edited except the ones listed under "By hand" below.

**Audit A — every doc mention that names an enum constant beside its code.** One hit, and it is a


**Audit B — every doc mention whose surrounding prose shares no vocabulary with the code's own
message.** 21 flagged, 20 read as false positives on inspection (`KMS-400021 NOT_PERMITTED` beside
"Refused", and so on). **One was a real defect the mechanical sweep introduced**, and it is the most
important thing on this page:

```
docs/stories/EPIC-2-recipe-library-DESIGN.md:660 KMS-400106=KITCHEN_NAME_TAKEN | Your temple already has a kitchen with that name.
    | `KMS-400106` | Only a platform operator can change the recipe library. |
```

That design document *proposed* `KMS-4972` for a library-permission refusal. It was never built, and
`4972` was later allocated to `KITCHEN_NAME_TAKEN` in Epic 10. Mapping it mechanically made the
document assert something false. **Reverted to `KMS-4972`, marked "proposed, never built."** The
same treatment was given to the `KMS-4969` row on the line above it.

**Audit C — bare four-digit numbers used as codes without the `KMS-` prefix.** Found by matching
every old number as a standalone token across the in-scope tree. Eight real hits, all fixed by hand
(below); one intentional non-hit, `MoonData.java:100`, where `4987` is astronomical data.

**Audit D — anything that parses the code's shape.** Grepped `frontend/` and `backend/src/main` for
`\d{4}` patterns, `startsWith("KMS`, and `substring` near codes. Nothing parses a code; every call
site names the enum constant, exactly as the brief said. The only two places that depended on the
digit count were the two `ErrorCodeTest` lines.

### By hand — everything not driven by the map

- `ErrorCode.java` class doc: rewritten for the new scheme, saying plainly that the hundreds no
  longer carry meaning, why the bands went, and why six digits rather than four.
- `ErrorCode.java`, five interior comments whose *reasoning* was about the abandoned bands
  (`EQUIPMENT_SERIAL_ALREADY_USED`'s out-of-band paragraph, the `4017` note, the
  `PERSON_ALREADY_EMPLOYED` rename note, the retired-`4927` note, the events `4990-4993` note, and
  the "Bands are deliberate" heading). The historical facts are kept; the claims that are no longer
  true — "the block steps from 4016 to 4101", "a gap is cheaper than a renumber" — are re-anchored
  to the old scheme. **This is more than "only the number" and is a judgement call**: leaving a
  comment reading *"4014 was taken … and a code that has shipped is never renumbered"* inside the
  file that had just renumbered everything would have been self-contradicting.
- `ErrorCodeTest.java` lines 88 and 97 → `\\d{6}` and `/ 100000`, both tests kept, both comments
  updated. The `@DisplayName` and the class's own `KMS-nnnn` reference went to `KMS-nnnnnn`.
- `KMS-4172`, a made-up example code appearing 4 times (`ErrorCode` ×2, `ErrorResponse` ×1,
  `DESIGN_SYSTEM.md` §7 ×1) → **`KMS-500002`**. The design-system example is verbatim
  `WHATSAPP_SEND_FAILED` ("download the PDF and share it manually"), so it is now a code a reader
  can actually look up. It had to change to something: leaving a four-digit example would have
  undermined the disjointness the whole exercise is for.
- `KMS-nnnn` → `KMS-nnnnnn` in the 6 in-scope files that use the placeholder form, including
  `PROJECT_COMMANDMENTS.md` §6.
- Bare-number fixes: `UAT-069` ("`4979`, `4980`, `4981` and `4978` each say a different thing" →
  the six-digit codes); `SESSION_HANDOFF.md` ("(4002)"); `EPIC-3` ×3, `EPIC-4` ×1, `EPIC-10-DESIGN`
  ×1, `EPIC-2-DESIGN` ×3 — all historical numbering notes, marked "old-scheme" rather than rewritten,
