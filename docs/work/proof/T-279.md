# T-279 — one Indian-grouping helper for the backend: ₹1,00,000, not ₹100,000 (F6)

## Where "₹100,000" actually showed (the defect is real)

The JDK groups en-IN in threes. Measured with jshell on the build's JDK:

```
$ java -version  ->  openjdk version "21.0.12" 2026-07-21
NumberFormat.getNumberInstance(en-IN): 100000 -> 100,000 | 12345678.5 -> 12,345,678.5 | 150000 -> 150,000
```

Every backend place that used it, and so printed lakhs wrong:

- Split-gift thank-you WhatsApp/email text (`MonetaryDonationService`, template `WISHLIST_GIFT_SPLIT`): amount, applied and remainder via `donation/Rupees`.
- Donations ledger, the "Wish list: X (₹…) and general kitchen (₹…)" label (`DonationLedgerService:442`) via `Rupees`.
- 80G donation receipt PDF, the amount (`DonationReceiptService:151`) via `Rupees`.
- PO sheet (PDF and print view): every quantity ("150,000 pieces") via `Quantities.say()`, and pack counts via `DocumentGenerationService.say()`. The sheet's rupees were already right (T-268's `SheetRupees`).
- Every other `Quantities` text: job cards, work orders, low-stock messages.

The control run below reproduces it on demand: with the grouping put back to threes, the ledger returned `Wish list: Kitchen range (₹100,000) and general kitchen (₹50,000)`.

On screen: the web app uses `Intl` en-IN and was already right. Measured on the running app (localhost:3000, /invoices, signed-in session already in the Chrome tab group): page text reads `VERIFY-T068 Vishwa Packaging & Supplies Direct ₹5,00,000 — Voided`. No other ≥ ₹1 lakh figure existed on /donations or /invoices. No data was created.

## Behaviour below a lakh is unchanged

`IndianNumbersTest.unchangedBelowALakh` compares the helper with the old `NumberFormat` en-IN output for 20,000 seeded values from -99,999.9999 to 99,999.9999 at every decimals pair a caller uses: (0,0), (2,2), (0,2), (0,3). Same rounding (half-even), same trailing-zero dropping, same "-0". Green.

Two things kept on purpose: `Rupees` still writes a negative as "₹-500" (its old form; neither caller passes one), and `SheetRupees` still writes "-₹1,500".
