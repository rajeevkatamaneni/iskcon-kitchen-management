**Acceptance criteria:**

- Two temples, each holding a "Toor Dal" and a low item. This is T6's `McpStockFixture`:
  - temple A: dal 2 of 5, and 54 low items in all
  - temple B: dal 100, and Basmati Rice low
  - each temple has its own Kannada glossary entry for dal
- `initialize`, `notifications/initialized`, `tools/list` and `tools/call` for both tools, over HTTP at `/mcp`,
  using tokens from `AgentTokenService.mint`. Covered by `eachTempleSeesOnlyItsOwnStock`.
- A's token sees only A's rows, and B's token only B's:
  - `get_inventory("dal")`: one row each. A gets on hand 2 and A's Kannada; B gets 100 and B's Kannada.
  - `get_inventory()` for B: exactly Toor Dal and Basmati Rice.
  - `list_low_stock` for B: exactly Basmati Rice.
  - `list_low_stock` for A: 50 returned, truncated, and Basmati Rice not among them.
- No token: 401 with an empty body.
- Expired token: 401. It is signed with the server's key and expired 5 minutes ago.
- Disabled user: the same token gets 200, then 401 once the user row is set to DISABLED.
- A valid token for a person without MANAGE_INVENTORY: tested with a Volunteer. The test first asserts that
  `RolePermissions.forRole(VOLUNTEER)` lacks MANAGE_INVENTORY, so a later change to that policy fails
  loudly. How the model sees the refusal:
  - HTTP 200, a normal JSON-RPC `result` and no `error`
  - the tool result has `isError: true` and its text is exactly `NOT_ALLOWED_MESSAGE`: "This person's
    role does not include the stock screen, so I cannot read stock for them. A Temple Admin can say who
    should see stock."
  - checked for both tools; no stock name appears in the text

  So the model gets a tool result it can read and pass on. A bad token is different: the chain refuses
  it with a bare 401 before any MCP processing, and `claude -p` sees a failed connection, not a tool
  result.
- Also kept from McpTransportIT: a token without `agent:read` gets 403, and GET /mcp gets 405.
- T6's test-only security stand-in is removed and the suite has one fewer context. See "Context count".
