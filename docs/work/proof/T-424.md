# T-424 — A counted box will not take a fraction

Every quantity box in the application now asks one named function what `step` to carry, and a box
holding a count of indivisible things (`PIECES`, and whatever counted unit is added next) refuses a
fraction before it can be typed. The five screens whose boxes sit outside the shared `<Form>` say
the same sentence as the rest, from the same function. Nothing already stored is rewritten.

## What was built

### 1. The rule, said out loud

`Unit.java` already names the concept: `Family.MASS`, `Family.VOLUME`, `Family.COUNT`. The frontend
had no such thing — a count was identified by being *missing* from `FAMILY`, the large/small
conversion-pair table. `format.ts` now mirrors the server:

```ts
const UNIT_FAMILY: Record<string, UnitFamily> = {
  KG: "MASS", GM: "MASS", L: "VOLUME", ML: "VOLUME", PIECES: "COUNT",
};
export function isCountedUnit(unit) { return unitFamily(unit) === "COUNT"; }
export function stepForUnit(unit) { return isCountedUnit(unit) ? "1" : "any"; }
```

**Keyed so the next counted unit inherits it.** Adding crates or sacks — which `Unit.java` names as
the ones it expects — is one line here plus `FOOD_UNITS` plus a label, and all 26 boxes start
refusing fractions of it with no second sweep.

**Two tables, and a test that stops them drifting.** `FAMILY` stays as it is; it answers "what does
this convert into", which is a different question, and `PIECES` is rightly absent from it. The two
are pinned to each other through exported behaviour (`convertQuantity`, `portionUnitsFor`) rather
than by exporting the private table.

**The permissive edge.** An unknown or missing unit is **not** counted, so `stepForUnit(null)` is
`"any"`. A form where no ingredient has been chosen has no unit, and a box that refused a fraction
because its unit was blank would be a new defect in place of the old one.

### 2. Every box asks the helper

26 boxes now carry `step={stepForUnit(...)}` (or a documented pack conditional). The 16 files still
holding a literal `step="any"` hold money or coordinates, and `counted-units.test.ts` pins that list
by file with a reason for each — so a new quantity box written with `step="any"` fails a test rather
than quietly joining the defect.

A box whose unit can change follows it, because `step` is computed in render. Proved with the real
picker in `recipe-form-units.test.tsx` ("Measured in" KG → PIECES) and with a prop change in
`counted-quantity-boxes.test.tsx`.

### 3. The five screens outside `<Form>`

One new export, `formMessages.wholeNumberProblem(name, step, value)`, wrapping the existing
`wholeNumber`. **It takes the box's own `step`, not the box's unit**, so the attribute and the
sentence read the same value and cannot disagree about whether a box is counted.

| Screen | Where the sentence goes |
|---|---|
| `RecordDeliveryPanel` | its existing `problems(l)`, which already drives a red slot under Received now; a matching slot added for Rejected on delivery, which had none |
| `ingredient-requests/[id]` | new `tried` flag, sentence under each line's box |
| `inventory/page` | new `tried` flag on the in-place `EditRow`, sentence under the level |
| `shopping-list` | the line box refuses **on blur** and does not commit; the add box refuses as typed and disables Add |
| `MealServices` (`RecordMeal`) | a `basis-full` red line under the dish row, the same shape `KitchenSections` uses for `Form`'s slot |

**Naming.** Each sentence uses the box's own accessible name, so the screen-reader name and the
visible sentence match — which is what `Form` does. Two exceptions and one wart, below.

### 4. Nothing stored is rewritten

`step` governs what the browser accepts on a save, never what a box displays. Measured in a real
browser: the Inventory list renders "88.5 pieces" and "7.2 pieces" for the seeded rows, and pressing
*Everything arrived* on a delivery line owing 88.5 aprons fills the box with **88.5**, not 88 or 89.
Four tests assert a prefilled fraction still renders (delivery, planner band, recipe yield, approved
issue line).

## Two things the brief got wrong that would have shipped as defects

Both found by the full suite and by asking "is there a problem now that was not visible before".

### A pack line at the gate must still take part of a bag

The brief's precedent — *"a vendor sells whole bags: a pack line's box counts packs"* — is about
**ordering**. It is not true of **receiving**. `RecordDeliveryPanel` has supported a partial bag on
purpose since T-266, and the repo tests it:

```
it("accepts part of a pack: 2.8 bags still to come reads so, and sends 70 Kg")
```

My first version put `step="1"` on that box and broke it. Stepping the pack box by 1 would leave the
person at the gate unable to write down what actually arrived — a worse defect than the one being
fixed. **Corrected:** a pack line's box keeps `step="any"`, and the whole-number rule moves to the
**stock amount** instead, which is the figure that actually cannot be fractional — 2.8 boxes of a
dozen aprons is 33.6 aprons. Two tests cover it: 2.8 boxes of 12 is refused, 3 boxes is accepted.

### A bill has to be able to restate that delivery

Same reasoning, reached by thinking rather than by a failing test: `InvoiceItemsTable`'s billed
quantity had become `step="1"` for any pack line. A bill restates a delivery, so a bill for the 2.8
bags above would have been impossible to type. **Corrected:** only a line billed in a *counted unit*
steps by 1; a line billed in a pack stays free, with the server's refusal as the guard.

## Judgement calls

**Reorder threshold — counted.** A threshold is compared against a stock level, so it is whole
exactly when the level is. "Tell me when aprons drop below 3.6" is a rule nobody can read off a
shelf. Both threshold boxes (`InventoryItemForm`, the in-place row on `inventory/page`) follow the
ingredient's stock unit. An existing fractional threshold still renders and is refused only on Save.

**Pack size — counted.** A pack size is how much is in one pack, in the unit chosen beside it. A
pack of 12.5 pieces is not a pack of anything; a 2.5 Kg pack is ordinary. Applied in all three places
that ask (`PackSizes`, `vendors/[id]`, `InvoiceItemsTable`'s add-a-pack row).

**Left alone**, per the brief: money and prices (vendor rate, expected price, bill amount, credit,
market rate, stock value, indicative cost, wishlist price, donation value and cash), latitude and
longitude, lead times, head counts, and "weeks between repeats" (already `step={1}`).

**`inputMode` — added, not asked for.** `step="1"` changes what the browser accepts but not what a
phone offers to type with, so a counted box would have gone on presenting a decimal point that the
same box then refuses. `inputModeForUnit` gives a counted box `numeric` and everything else
`decimal`. No layout effect — the measurements below confirm it.

## The negative control

`scratchpad/T-424-negative-control.sh`, log at `scratchpad/control-T-424.log`.

**Method.** Break the one function the whole rule hangs off — `isCountedUnit`, made to answer `false`
for everything, which is exactly the state the application was in before this task — and require
that the counted tests fail.

**Why the helper and not the call sites.** With 26 edits of nearly identical shape, a sweep over the
call sites is the single most likely thing to patch 25 of them, or 27, and leave the control proving
something other than what it says. One function is one anchor.

**The five guards, and the output:**

```

 Test Files  4 failed (4)
      Tests  19 failed | 38 passed (57)
vitest exit with the rule switched off: 1   (required: non-zero)
=== control satisfied: switching the rule off makes the counted tests fail ===
RESTORED: lib/format.ts is byte-identical to the pristine copy again.
```

1. `set -e` **and** `trap restore EXIT` — only a trap survives a kill from outside the script.
2. `grep -c -F` the anchor, assert `== 1`, abort without writing if not. Printed above: `1 (required: 1)`.
3. The anchor is a whole return statement, `  return unitFamily(unit) === "COUNT";`, not a fragment.
4. `cmp -s` against a pristine copy **proves the file on disk changed**. `git diff --stat` could not
   be trusted here: two other builders are writing in this worktree.
5. Every artefact is named for the task — `control-T-424.log`,
   `control-T-424-format.ts.pristine` — because the scratchpad is shared.

**Restore verified independently of the script:**

**The 19 that failed** span every layer: the rule itself (`says PIECES is a count…`), the keypad,
