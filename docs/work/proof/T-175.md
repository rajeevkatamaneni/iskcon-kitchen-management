- press again: each sentence shows once, beside its box.

## Why it survives against today's code

The two forms on the page are both rendered by `ShiftRosterView`. Every re-render a person can cause
there, such as opening the update box, or going busy on a save, re-renders the empty removal `Form` too.
Its layout effect runs `sync()` after every render. That is a safety net, but control 2 shows it is
never needed: nothing ever moves the slot.

The reason is how React inserts nodes. A new node goes in before the next node React itself rendered,
never after the box. The slot is not one of React's nodes. So a node added after the label lands after
the slot, and a node added before lands before the label. React only changes attributes in place
(`disabled` on the buttons) and replaces text in place. It never touches the slot, `aria-invalid` or
`aria-describedby`, because none of them is a prop it rendered.

The observer watching only the empty removal form is therefore harmless on this page. It sees nothing,
and nothing needs seeing. The only React change that could put a node between a box and its slot is
moving the box itself, for example a keyed list of boxes being reordered. No form on this page does that.
