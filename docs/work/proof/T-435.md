## The audit — every page heading against its menu label

**Reported only. Nothing outside `/kitchens` was changed.**

### How it was extracted, so it can be repeated

Script: `scratchpad/T-435/audit-T-435.mjs`, run as
`node audit-T-435.mjs /Users/Rajeev/Workspace/kms-three-small/frontend`.

- **Menu side:** every `href: "…", label: "…"` pair matched out of `lib/nav.ts` by regex. 41 pairs.
- **Page side:** for each of the 101 `app/**/page.tsx`, the route is the path with `app/` and
  `/page.tsx` stripped. JSX comments are stripped first (`{/* … */}`), so a commented-out `<h1` is
  never mistaken for the heading. Then, in order: the text of the first literal `<h1>…</h1>`; else
  the `title=` prop of the first `<PageHeader>` **or the `task=` prop of the first `<FocusScreen>`**
  (those are the two `components/ds` components that render an `<h1>` for their caller — missing
  `task=` is what first showed `/planner/reuse` as unresolved when it actually matches); else the
  last `<h1>` of a single delegated component, skipping the wrappers `RequireRole`, `Sidebar`,
  `ServerUnreachable` and `Loading`, which own an `<h1>` only for their *refusal* screen. Anything
  still unresolved prints as `UNRESOLVED` rather than being skipped silently.
- Only routes that exactly match a menu `href` are compared. That is 41 of 101; the other 60 are
  detail, new and edit pages with no menu item of their own, which the brief says are not expected to
  repeat a list's label. Every one of the 41 menu hrefs resolved to a page — the script's
  "menu hrefs with no page.tsx" line printed `(none)`, so nothing was quietly dropped.
