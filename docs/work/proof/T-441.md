# T-441 — Ingredients and Supplies follow Staff: the name opens it, the page has Edit, the edit screen has Save and Cancel

## The two things to check before building, checked

**1. Ingredients and Supplies are two list screens over one catalogue, and one detail page already
serves both.** `/ingredients` filters `!supply`, `/supplies` filters `supply`, both from the same
`api.listIngredients`. `/ingredients/[id]` already worked for either and already switched its back
link and sidebar on `ingredient.supply` ("← All supplies"). So Supplies did **not** need a detail
page of its own, and does not have one: its names link to `/ingredients/<id>`, which is where the
pack sizes, price, vendors and Link a vendor Rajeev asked for already live. That is the smaller
change, and it is the one built.

**2. The ingredient detail page already existed and already showed all four "missing" fields.**
`IngredientFacts` prints Category, Stock unit, Ekadashi and Other names (aliases), plus Buying and
Added on. T-402/Q-10 added them on 2026-09-19, after the note Rajeev wrote. So the gap was not the
fields — it was that there was no way to *change* them except the editing row on the list. That is
what was built: `/ingredients/[id]/edit`.

## Judgement calls, stated rather than slipped in

1. **Save and Cancel return to the ingredient's own page, not to the list.** Staff's edit screen
   returns to the register (Rule 8: commit returns to the list with the confirmation waiting there).
   That rule was written when a form's only caller was a list; here Edit is pressed on the detail
   page, so the detail page is where the person was, and it shows the saved values themselves. Every
   other part of the shape is Staff's, unchanged. If Rajeev wants it to land on the list instead,
   it is one line in each of two places.
2. **"Move to Ingredients" on Supplies went with "Move to Supplies".** He named only the Ingredients
   one and gave his reason — "Not needed. they can delete and recreate as a supply" — and the reason
   reads the same in the other direction. Flagged here rather than assumed silently.
3. **The Ekadashi row is now absent on a supply's detail page**, and the facts card heading reads
   "About this supply". Before this task no supply had a page a person could reach, so neither read
   oddly; now they would. It is not a printing of the food/supply flag he ruled must not be
   displayed — the sidebar and back link already say Supplies.
4. **The "Not bought" checkbox stays on the detail page** rather than moving onto the edit form.
   `UpdateIngredientInput` has no `notBought` key: it is a separate audited route, like the pack
   sizes, the market rate and the vendors. Those four behave as Staff's documents and conduct notes
   do — each saves when pressed and none is undone by Cancel.
