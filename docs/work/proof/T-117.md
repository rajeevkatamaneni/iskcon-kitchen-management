## What the check is

`tools/check-tfvars-example.sh` parses variable names out of both files and takes the set
difference in both directions, because the two directions fail differently:

- **Declared but missing from the example** — a new environment is silently unconfigured. That is
  how this environment ended up with no `smtp_host` and an application that quietly did not send
  email.
- **In the example but no longer declared** — `terraform` refuses at the first step, with a message
  that reads like the operator mistyped something. Ours named `min_instances`, deleted long before.

It starts from the six-line sketch in `docs/work/proof/T-115.md` ("declared but missing from
example / in example but not declared") and is the same set difference, moved out of a throwaway
Python snippet into a script CI runs, with a parser that can be trusted and a failure mode that is
loud.

### What the parser does, and where it would be wrong

The brief asked this to be answered honestly, so, plainly: a `grep 'variable "'` is right until
somebody writes a comment or a heredoc containing that string, and a check that silently stops
matching is worse than no check because it reports success. This parser is one left-to-right
character scan per line that:

- strips `#` and `//` comments **while tracking double-quoted strings**, so a `#` inside a value is
  not a comment and a `#` outside one is;
- tracks heredocs (`<<EOT`, `<<-EOT`) and skips their bodies entirely;
- counts `{[(` depth outside strings and comments, and only looks at lines at **depth 0**, so a
  nested assignment in some future block is not mistaken for a top-level one;
- treats **anything at depth 0 it does not recognise as a parse error**, not a skipped line. A
  `locals` block appearing in `variables.tf`, an unbalanced brace, a file that ends mid-heredoc, a
  name assigned twice — each fails CI with the file, line number and the offending text;
- refuses `/* */` block comments outright, saying so. Neither file uses them, handling them
  properly needs real lexing, and handling them badly is how a check starts lying;
- refuses to report success if it parsed **zero** names out of either file.

**Where it is still wrong**, stated rather than discovered later: it assumes a variable block opens
on the same line as its name, so `variable "x"` with the `{` on the next line — legal HCL that
nobody writes — is reported as a parse error rather than parsed. It does not evaluate
interpolation or `for` expressions; it does not need to, since it only reads names. Every one of
those limits is an error, not a shrug, which is the property that matters.

## Not done / needs Rajeev

- **No hand smoke-test, and there is no surface to smoke-test.** This adds nothing a user can see;
  it adds a step to a build. Commandment 5's smoke test does not apply. The equivalent — watching
  the step run red and green on a real GitHub runner — needs a push, which is the release agent's
  step, not mine.
- **The check has not run on GitHub's infrastructure**, only locally and in an `ubuntu:24.04`
  container with the same `mawk` the runner uses. The first real run will be on the release
  agent's push.
- **`terraform.tfvars` itself is still unchecked**, and deliberately: it is gitignored, it holds the
  environment's real values, and CI has no copy of it. So this catches an example that has drifted
  from the declarations; it cannot catch a live environment whose `.tfvars` is missing a variable
  that has a default. Worth knowing, not worth a task — a defaulted variable is by definition one
  the environment can survive without naming.
- **No lock taken.** The script reads two files and writes none; the only heavier things run were
  `docker run` on throwaway containers and, for the controls, edits to two `infra/` files that were
  restored within the same command and verified clean. Nothing touched Gradle, `.next/` or
  `build/`.
- **One judgement worth naming:** I made an unrecognised construct in `variables.tf` a hard CI
  failure rather than something the parser skips. If somebody legitimately adds a `locals` or
  `terraform` block to `variables.tf`, CI goes red until this script is extended. I think that is
  the right trade — a drift check whose failure mode is "quietly matched nothing" is the exact
  thing being fixed — but it is a deliberate strictness and somebody will meet it eventually.
