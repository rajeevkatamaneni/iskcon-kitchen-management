# T-199 — Volunteer shifts screens on D-27: Post a shift without meal fields, meal labels, a meal shift's edit with read-only date and meal, the times-changed warning, and the "moved" flow removed

## Files changed (all inside the contract)

- `frontend/app/volunteers/shift-form.tsx` — labels *Start* / *End* became *Start time* / *End time* (order was already the ruled one: Title, Date, Volunteers requested, Start time, End time, Location, Reminder hours before, Description). New optional `meal` prop: the Date slot then shows the date and "For Lunch." as words with a link **Open this meal** → `/planner/meal/<mealId>`, and renders no date input at all. The planner's `fixedDate` path is untouched. New exports `MealOfShift`, `mealOfShift(shift)`, `mealLabel(shift)` ("For Lunch, 15 September", using `dayRange(d, d, false)` from `lib/format.ts`, so the year appears only outside the temple's current year; event by its own name; null for a plain shift). Removed `moved` and `movedUnderRoster`.
- `frontend/app/volunteers/moved-notice.tsx` — deleted.
- `frontend/app/volunteers/new/page.tsx` — the sentence "Kitchen help for a meal? Ask from that meal in the planner." above the fields, "in the planner" a link to `/planner`.
- `frontend/app/volunteers/[id]/edit/page.tsx` — passes `meal` for a meal shift and sends `shiftDate` back exactly as read; times warning before saving (reuses `timesChanged`, `timesChangedWarning` from `ShiftLayer.tsx` and `ConfirmLayer` from `confirm-layer.tsx`, title "This shift has new times", buttons *Go back* / *Save changes*); `?moved=` gone. - `frontend/app/volunteers/page.tsx` — `MovedNotice` and `moved` param handling gone; meal label under the shift's title.
- `frontend/app/volunteers/[id]/page.tsx` — meal label under the roster heading.
- Tests: `__tests__/volunteer-shifts.test.tsx` (edited), `__tests__/shift-attendance.test.tsx` (one test added), `__tests__/shift-edit-keeps-meal-link.test.tsx` (comment pointer only), `__tests__/shift-edit-meal-shift.test.tsx` (new, allowed by the `shift-*.test.tsx` rule).
- Not changed: `lib/api.ts` (T-198 left it right for this), `app/my-shifts/page.tsx`, `app/shifts/page.tsx` (see Not done), `ShiftLayer.tsx`, `MealComposer.tsx`, `confirm-layer.tsx`, `planner-shift.test.tsx`, `design-system.test.ts`. No backend file.

## Acceptance criteria

1. **Post a shift** (`volunteer-shifts.test.tsx`): "asks for exactly the eight ruled fields…" checks every input's own label in DOM order equals the ruled eight, and names in the same order; no checkbox, select, combobox, or "Capacity". "says where kitchen help for a meal is asked for…" finds the `<p>` whose text is exactly the sentence, and "in the planner" is a link to `/planner`. "posts a request with no meal field in it" checks the request's sorted `Object.keys` equal the eight `ShiftInput` keys and none matches `/meal/i`.
2. **List labels** (`volunteer-shifts.test.tsx`): a Lunch shift's row has "For Lunch, 15 September"; an event row has "For Janmashtami, 16 September" and no "For Event"; a plain row has no `\bFor `. Fixtures use this year, so the label is year-free whenever the suite runs; a second test shows a next-year date reads "For Lunch, 2 January <year>". Roster heading also labelled (`shift-attendance.test.tsx`, "labels a meal shift's roster…").
3. **Edit a meal shift** (`shift-edit-meal-shift.test.tsx`): no `input[name=shiftDate]` and no date input; "15 September" and "For Lunch." shown as text; link "Open this meal" → `/planner/meal/meal-lunch` (and `meal-janmashtami` for an event); no checkbox/select/"not for a meal". Saving changes to title, capacity, location, reminder and description sends one request with no dialog, `shiftDate` key present and equal to the read date, `mealId` unchanged, then back to the list. A KMS-400153 rejection shows the message and code in the error notice. A plain shift still changes its date and sends the new one (`volunteer-shifts.test.tsx`, "lets a shift not for a meal change its date…").
4. **Times warning**: with 3 signed up, a changed start (and separately a changed end) opens an alertdialog with exactly "3 volunteers are signed up. They’ll be told the new times." and `updateShift` not called; confirming sends once. 1 → "1 volunteer is signed up. They’ll be told the new times." 0 signed up (with a waitlist) → saves, no dialog. Unchanged times with 3 → no dialog. Go back → nothing sent. `document.body.textContent` does not match `/\bmoved?\b/i`, before and with the dialog open. The apostrophe is the curly one, because the sentence comes from T-198's `timesChangedWarning`, reused rather than copied.
5. **Moved flow**: *corrected by Send-back 1.* The first pass deleted it; that was wrong for a plain shift's new date. It is restored for that case only (`dateChangedUnderRoster`), and `movedUnderRoster` stays gone. See Send-back 1.
6. **Negative control**: two, each failing the matching tests, restored and `cmp`-checked; output above.
7. **Full checks**: green, `planner-shift.test.tsx` included (27 passed in the targeted run, in the 138 files of the full run).
8. **Hand smoke test**: not done. The stub-auth / API-stub harness is not in the tree, and building it means editing `lib/firebase.ts`, `lib/auth-context.tsx` and `app/api/`, which are outside my paths.
