## Final strings, verbatim (for the UAT script)

Day card, event only:
- Opener button: `Repeat this event` (was "Repeat weekly", which is no longer true once the gap can be 2 to 12)
- Sentence: `Repeat <event name>` · `once every` [box] `week` (or `weeks` when N > 1) · `until` [date] · (i) · `Repeat` · `Close`
- Box names for screen readers: `Weeks between repeats`, `Repeat until`. The (i) is `More about repeating an event`, and it says: `Each copy can be edited or cancelled on its own. The copies stay linked, so you can cancel the later ones together.`
- Live count: `Makes 8 copies · last one Sat 26 Dec 2026` / `Makes 1 copy · last one Sat 3 Oct 2026` / `Makes no copies. Choose a later end date.`
- Preview skips: `Skips Sat 10 Oct 2026: a dish doesn’t suit the fasting day.` / `Skips Sat 17 Oct 2026, Sat 31 Oct 2026 and Sat 14 Nov 2026: this event is already planned those days.` (`that day` for one date)
- Inline refusals (red text, no banner; Repeat disabled): `An event can repeat every 1 to 12 weeks. Choose a number from 1 to 12.` / `No copies fit before that end date. Choose a later end date, or repeat more often.` / `The end date has to be within a year from today. Choose an earlier end date.` / `Choose the date to repeat until.` The server wrote the last three itself.
- After Repeat (green notice, because this is the person's own action succeeding): `Made 6 copies · last one Sat 26 Dec 2026.` then `Skipped Sat 10 Oct 2026: a dish doesn’t suit the fasting day.` / `Skipped … : this event is already planned that day.` If nothing was made: `No copies were made.`
- Series line (neutral grey text with a repeat icon, not a pill): `Repeats every 2 weeks until 31 Dec 2026 · event 3 of 8`, `Repeats every week until …`. On a cancelled occurrence the position is left off.
- Edit page: `Repeats every 2 weeks until 31 Dec 2026 · event 2 of 7. Changes here apply to this date only.`

Cancel dialog (the existing ConfirmLayer):
- The group label (legend): `This event repeats. Which do you want to cancel?`. Radios: `Just this event` (the default) and `This and all later ones`.
- Just this one: the body is unchanged (`Its preparations come off the plan.` or the volunteer-shift warning) and so is the button (`Cancel this meal`).
- This and all later ones: `Cancels this event and 4 later ones, the last on Sat 26 Dec 2026.` / `Sat 14 Nov 2026 was changed on its own and will be cancelled too.` (plural: `… and … were changed on their own …`) / `3 volunteers are signed up or waiting across these events, and will be told.` or `No volunteers are signed up for any of them.` The button reads `Cancel 5 events`.
- After: `<name> was cancelled on 4 dates.` + ` 3 volunteers were told.` when there are any. Just this one: `<name> was cancelled.` as before.
- On KMS-400179 the dialog stays open. It shows the fresh list and the server's notice: `The later events changed while you were deciding, so nothing was cancelled.` / `Look at the list again, then confirm.` / `If you need help, quote KMS-400179`.

## Not done / needs Rajeev

- **Where I departed from the brief** (each is small and easy to reverse):
  1. The opener says "Repeat this event" instead of "Repeat weekly", which would be wrong at every 2 or more weeks.
  2. The later ones are read when Cancel is pressed, not when "later" is chosen. That way the dialog knows before it opens whether to ask at all, and never changes shape under the reader. The button is busy for that one request.
  3. A refusal after pressing Repeat now shows inside the panel (ErrorNotice) instead of the page banner, as the preview's refusals do.
  4. The outcome is a green success notice. It used to be grey text.
- **The native date box follows the device**, so headless Chromium showed `11/14/2026`. That matches the standing date-format decision (native pickers are left alone). Every date the app writes itself is day-first.
- **The series line always shows the last gap asked for.** Repeat every 2 weeks, then extend every week, and it says "every week" (server behaviour, T-307).
- **The past-date floor is client arithmetic only.** It matches T-310. Until T-310 lands the server may still count a past date, but the planner offers Repeat only on a day that has not passed, so in practice it cannot come up.
- **Checked only in headless Chromium**, at 1280, 1024 and 390, with a 44-character test name. Not checked in Rajeev's Chrome, at 200% zoom, or on a real phone.
