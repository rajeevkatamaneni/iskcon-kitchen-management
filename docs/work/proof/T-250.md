## The library import's parsing rule

For each library line, `RecipeImportService.resolveIngredients` works in this order:
1. `IngredientNameMatcher.split(name)` gives the **base** and the **note**. The rules are T-249's, recorded in `docs/work/proof/T-249.md`.
2. `IngredientNameMatcher.findMatch(base, catalogue)` checks the base against every ingredient in the temple and every alias in `ingredient_aliases`. RLS scopes both queries. The list is loaded once per import, oldest first, so a tie goes to the ingredient the temple has had longest. Each ingredient the import creates is added to the list, so the recipe's second coconut line finds the Coconut the first line just created.
3. Then one of three things happens:
   - **EXACT:** the line uses the existing ingredient, and the note goes on the line.
   - **No match:** the import creates **only the base**, marked `library_derived` and in the line's unit. The note goes on the line.
   - **CLOSE only: HELD on Q-11.** This is `heldCloseMatch()`, one isolated method. It does what the import did before: it does not take the close ingredient, and creates a new one. What it creates is still the base, with the note on the line, because R-DUP-1 ("a preparation is never an ingredient") applies whatever Q-11 decides. Rajeev's answer changes only this method.

What the import tests show (`RecipeImportPreparationIT`):

| Library line(s) | The temple already has | Result |
|---|---|---|
| Green chilli, slit | Green chilli | no new ingredient; the line uses Green chilli with note `slit` (**the AC**) |
| Cashew, halved | nothing | creates **Cashew** (GM, library_derived); note `halved`; `ingredientsCreated` = 1 |
| Coconut, grated · Fresh grated coconut · Green chilli, slit · Green chillies | nothing | creates Coconut and Green chilli only (2); notes `grated`, `fresh grated`, `slit`, none |
| Dahi, whisked | Curd, with the alias row "Dahi" | uses Curd; note `whisked` |
| Rice, broken | nothing | creates "Rice, broken" with no note (a store-bought form, not a preparation) |
| Jaggary, grated · Tomato, ripe | Jaggery, Tomato | **HELD:** creates "Jaggary" (note `grated`) and "Tomato, ripe" (no note) |
| Green chilli, slit, in temple A | Green chilli, in temple B only | temple A gets its own Green chilli; temple B's is never matched |
