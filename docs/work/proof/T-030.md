# T-030 — `/donate` narrows to `VOLUNTEER` alone, at both ends

**What was built:** the page guard on `frontend/app/donate/page.tsx` now reads
`<RequireRole roles={["VOLUNTEER"]}>` (was `["TEMPLE_ADMIN", "KITCHEN_MANAGER", "KITCHEN_STAFF",
"VOLUNTEER"]`), matching the `nav.ts` row the work manager had already narrowed to
`roles: [VOLUNTEER]`. Tests that assumed the old, wider shape were rewritten to prove the new one.

**Files changed** (all inside the T-030 contract):
- `frontend/app/donate/page.tsx` — guard narrowed to `["VOLUNTEER"]`, with a comment stating why
  (employed people already serve, which is the donation; it is a guard and not just a hidden menu
  row because a screen reached by typing the URL is still tone-deaf) and referencing D-8.
- `frontend/__tests__/nav.test.ts` — added an explicit `expect(hrefs).not.toContain("/donate")`
  assertion (with a one-line D-8 comment) to the `KITCHEN_STAFF`, `KITCHEN_MANAGER` and
  `TEMPLE_ADMIN` cases. The volunteer case already asserted `/donate` present
  (`hrefsFor("VOLUNTEER")).toEqual(["/my-shifts", "/shifts", "/donate"])`) and needed no change.
  I did **not** touch the `/my-shifts` "kitchen staff can offer seva too" comment at line 37 — that
  assertion is about a different route governed by D-10, which this task is explicitly scoped away
  from (T-030 is D-8's donations half only), and its premise (a cook may still offer seva via
  `/my-shifts`) is still true today.
- `frontend/__tests__/donate-signed-in.test.tsx` — converted the static
  `vi.mock("@/lib/auth-context", ...)` to a mutable `authRef` (via `vi.hoisted`) so a test can
  render the real route as a role other than volunteer; added a `beforeEach` that resets it to
  volunteer for every existing test (so their behaviour is unchanged); added two new tests:
  `"refuses a cook — already serving is the donation, so the page is not theirs"` (`KITCHEN_STAFF`)
  and `"refuses the temple admin too — an admin app should not ask its own admin for money"`
  (`TEMPLE_ADMIN`). Both render the real `DonateRoute` (dynamic import, same pattern the existing
  "the /donate route itself shows exactly one lotus" test already used) and assert `"Not your
  page"` renders and the `"Donate money"` tab does not.
- `frontend/__tests__/donate-checkout.test.tsx` — **not changed.** It renders `DonatePage` directly
  (never the route, so it never exercises `RequireRole`) and its fixed `useAuth` mock was already
  `role: "VOLUNTEER"` — there was no non-volunteer case in it to fix, and it needed no new
  volunteer-refusal proof since it never proved a non-volunteer could reach the page in the first
  place. Re-ran it to confirm it's unaffected (below).
- `docs/work/proof/T-030.md` — this file.

**Not touched:** `frontend/lib/nav.ts` (reserved — already correctly edited, confirmed by reading
it), `frontend/__tests__/donations.test.tsx` (checked: it exercises `/donations`, the admin ledger
page, not `/donate` — unrelated, confirmed no `RequireRole` conflict), `frontend/__tests__/role-refusals.test.tsx`
(checked: doesn't mention `/donate` at all — unrelated), the backend (out of scope per D-8 — no
migration, error code, permission or Java change was made or needed).

## Acceptance criteria

- **`frontend/app/donate/page.tsx` guards on `["VOLUNTEER"]` alone.** Done — read back, and covered
  by the two new refusal tests below.
- **A test proves a `KITCHEN_STAFF` (and at least one of `TEMPLE_ADMIN` / `KITCHEN_MANAGER`) is
  refused the page.** Done, at two levels:
  - `donate-signed-in.test.tsx`: `"refuses a cook — already serving is the donation, so the page is
    not theirs"` (renders the real `DonateRoute` as `KITCHEN_STAFF`, asserts `"Not your page"` and
    no `"Donate money"` tab) and `"refuses the temple admin too — an admin app should not ask its
    own admin for money"` (same, as `TEMPLE_ADMIN`).
  - `nav.test.ts`: the `KITCHEN_STAFF`, `KITCHEN_MANAGER` and `TEMPLE_ADMIN` cases each now assert
    `expect(hrefs).not.toContain("/donate")`.
- **A test proves the `/donate` nav row is not offered to `ADMIN`, `MANAGER` or `KITCHEN`, and is
  offered to `VOLUNTEER`.** Done — the three new `not.toContain("/donate")` assertions above, plus
  the pre-existing `hrefsFor("VOLUNTEER")).toEqual([..., "/donate"])` assertion (unchanged, already
  correct).
- **No test was deleted or skipped to make the suite green.** Confirmed — every edit either added
  an assertion or converted a mock to be parametrisable; no `it(...)` block was removed and no
  `.skip`/`.todo` was introduced. `git diff --stat` on the three test files shows only additions
  plus the one mock-shape change in `donate-signed-in.test.tsx` (static object → `authRef`), which
  is additive (existing tests behave identically via the `beforeEach` reset).
- **The whole frontend suite is green.** `Test Files  90 passed (90)` / `Tests  945 passed (945)`,
  pasted in full above.
