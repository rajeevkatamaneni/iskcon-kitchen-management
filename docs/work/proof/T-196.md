## How it is built, for the next reader

- **Planning** (`MealPlanService.create`): kind by id → head count, event chain, occasion, recipes, Ekadashi per dish → find or create the day (`ON CONFLICT (tenant_id, plan_date) DO NOTHING`, day type written once) → find the meal `FOR UPDATE` by day, kind id and `lower(COALESCE(event_name,''))`, else insert with `ON CONFLICT` on exactly V136's index expression → write the meal's facts → insert dishes → `ShiftService.saveForMeal` last → audit read back from the rows. One `@Transactional`. T-197's `saveForMeal` and `cancelForMeal` are `Propagation.MANDATORY`, so they cannot run outside it.
- **Update** takes no date or kind. The dish list is the whole list.
- **Cancel** cancels PLANNED dishes and calls `cancelForMeal` (which answers 0 when there is no live shift) in the same transaction.
- `MealPlanService` takes `ShiftService` through `@Lazy`, so a future constructor dependency from `shift/` back into `meal/` cannot stop the application starting. `ServedMealService` no longer depends on `MealPlanService`; the dependency runs one way.
- **Reads** (`ServedMealService.list/find`): one meal query joining day, kind (for the name) and users, one dish query, grouped by `meal_id`. Dishes are ordered by `created_at, id`. `MealCorrectionIT`'s order-dependence pair used to vary `ready_by` per dish; ready-by is the meal's now, so the pair varies insertion order instead, and both orders still pass.
- **Committed stock and sufficiency** key claims by dish id (`MealClaim.dishId`) and order by day, meal ready-by, dish `created_at, id` — the same order in both, as before.
- **Job card version** reads and writes `meals.card_version/card_fingerprint` `FOR UPDATE`. The old "preview a meal with no row, print v1, remember nothing" branch is gone because every meal has a row.
- **Kind delete** relies on the foreign key: `DataIntegrityViolationException` → `KMS-400126`.

- The meal, its dishes and the shift are one transaction. Any refusal — a dish, the head count, the Ekadashi check (`KMS-400048`), the shift — saves nothing.
- **Find or create**: a meal already on that day with that kind and the same event name ignoring case is reused, including a cancelled one. The response carries that meal's existing id; the meal's facts are overwritten with this request's, and the dishes are **added** to it. A meal already recorded is refused `KMS-400098`.

**`PUT /api/v1/meals/{id}`** — "Update this meal". Body `UpdateMealRequest`: the same fields as `SaveMealRequest` **minus `planDate` and `mealKindId`** (a meal is not moved; plan the new one and cancel this one). `dishes` is the whole list:
- `{id, recipeId, targetYield}` keeps and changes that dish (must be this meal's and still PLANNED: otherwise 404 `KMS-400030` / 409 `KMS-400046`);
- `{id: null, ...}` adds a dish;
- a PLANNED dish left out of the list is cancelled.
- `volunteerShift`: a draft creates or changes the meal's shift in the same transaction; **null leaves any existing shift exactly as it is**.
- `eventName` may change, but not onto another event's name that day (`KMS-400001`, field `eventName`).

Response **200** always (was 204 before): `{ "id": <mealId>, "warning"?: ... }`. Refused `KMS-400098` once the meal is recorded or any dish is cooked.

**`POST /api/v1/meals/{id}/cancel`** — body optional `{ "reason": string ≤500 }`. Cancels every PLANNED dish and the meal's live shift in one transaction; signed-up and waitlisted volunteers get the existing `shift_cancelled` message after commit (T-197). With no reason they are told "The meal this shift was for has been cancelled." Response **200** `{ "volunteersTold": int }` (was 204). A cooked or recorded meal: `KMS-400045`. Cancelling an already-cancelled meal is a quiet 200.

**`POST /api/v1/meals/{id}/repeat?weeks=1..52`** → `{ copied (dishes), weeksCopied, refusedOnFast }`. Copies the whole meal (all live dishes) onto the same weekday; no shift is copied.

**`GET /api/v1/meals/{id}/travel-estimate`** → `TravelEstimate` (unchanged shape).

**`GET /api/v1/meals/summary?from=&to=`** → `{ unrecorded: int, platesByMealKind: {label: plates} }` (was `/api/v1/meal-services/summary`).

**`POST /api/v1/meals/{id}/record`** — body `{ note?: string ≤2000, dishes: [{ dishId: uuid, actualServings?: number, consumedQuantity?: number, notMade: boolean }] }`. **No `planDate`, `mealKind`, `eventName`**; `mealPlanId` is renamed **`dishId`**. Response 200 `ServedMeal` (with `volunteerShift` null). Errors unchanged: `KMS-400098`, `KMS-400099`, `KMS-400009`, 404 for a dish not in this meal.

**`POST /api/v1/meals/{id}/correct`** (`CORRECT_RECORDED_MEAL`) — body `{ note: string (required), dishes: [{ dishId, actualServings?, consumedQuantity?, notMade }] }` (`mealPlanId` → `dishId`). Response 200 `ServedMeal`. Errors unchanged (`KMS-400137` second correction).

### Job cards (`/api/v1/job-cards`)

All addressed by `mealId` (query parameter) instead of `date` + `mealKind` + `eventName`:

- `POST /api/v1/job-cards?mealId=&language=` → 202 `{documentId, cardNumber, status: "PENDING"}`
- `GET /api/v1/job-cards/languages?mealId=` → `{languages, defaultLanguage}`
- `GET /api/v1/job-cards/documents?mealId=` → `DocumentView[]` (404 for a meal that is not this temple's)
- `GET /api/v1/job-cards/print?mealId=&language=` → HTML
- `GET /documents/{documentId}` and `/documents/{documentId}/download` unchanged.

### Changed responses elsewhere

- `GET /api/v1/meal-plans/sufficiency` → `MealSufficiency`: `mealPlanId` renamed **`dishId`**; new **`mealId`** and **`eventName`**. Order: `dishId, mealId, planDate, mealKind, eventName, readyBy, recipeName, status, shortfalls, orderBy, orderUrgency`.
- `GET /api/v1/meal-plans/outside-commitments` → each row gains **`mealId`** (first field); `preparations` counts the meal's live dishes.
- `GET /api/v1/meal-plans/menu-history` → gains **`mealId`** (the meal that was cooked, or null).
- `GET /api/v1/inventory/items/{id}` → `committed[]` (`CommittedMeal`): `mealPlanId` renamed **`dishId`**, new **`mealId`**. Link to the meal by `mealId`.
- `GET /api/v1/today` → `meals[]` (`TodayView.Meal`) gains **`mealId`** (first field). `dishes[].id` is the dish id as before.
- `ServedMeal` itself: `serviceId` is gone, replaced by `mealId` (and `mealKindId`); it now carries every whole-meal fact listed above.
