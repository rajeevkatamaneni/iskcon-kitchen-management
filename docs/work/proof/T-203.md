# T-203 — a reason of only spaces, and a credit of 0, now show the red sentence instead of a silent press

**Files changed:** all 15 are inside the contract. No other frontend file is modified (checked with
`git status --short`; the backend and docs changes in the tree belong to other builders).

- `frontend/components/ds/Form.tsx`: two rules folded into the validity `Form` reads. (1) A
  `required` `<textarea>` or free-text `<input>` (text, search, tel, url, email, password) whose value
  is non-empty but only whitespace counts as `valueMissing`, so it reads "<name> is required".
  (2) An `<input>` with `data-more-than="N"` holding a number `<= N` counts as `rangeUnderflow`.
  An empty box is left to `required` and a half-typed one to `badInput`. Because both go through the
  same validity, the existing re-check while typing and the clear-when-fixed behaviour apply to them
  unchanged. There is a class comment explaining why.
- `frontend/components/ds/formMessages.ts`: `moreThan(name, min)` returns "<name> must be more than <min>".
  `ControlFacts.moreThan?` is optional, so older facts objects still type-check. In `messageFor`, a
  `rangeUnderflow` on a box with `moreThan` set returns that sentence before any date, time or
  at-least sentence.
- `frontend/app/invoices/[id]/page.tsx`: the credit box gains `data-more-than="0"`. The guard comments
  on void, credit and reverse are updated. The `if (!ready) return` and `if (written === "") return`
  twin guards are kept.
- `frontend/app/donations/page.tsx`, `frontend/components/VendorStatusDialog.tsx`,
  `frontend/components/staff/ConductNotes.tsx`, `frontend/components/planner/MealServices.tsx`
  (correction reason only): comments only. Each early `return` is kept as the twin guard.
- Tests: `form-wrapper` gains 6 behaviour tests and 2 sentence cases. `donation-void`, `vendors`,
  `blank-submit-slice-c`, `staff-conduct-notes`, `invoice-void` and `meal-correction` now assert the
  red sentence on the spaces press (and on the 0 press). `blank-submit-slice-d` gains a spaces test on
  a fresh conduct-note form. `slice-c` reopens the dialog so its spaces sentence cannot be left over
  from the blank press.

**Acceptance criteria:**

- Six sites, spaces: each test presses the real button with "   " in the box and asserts the exact
  sentence, red (`text-danger`), `aria-invalid`, and nothing sent. Then a real reason is pressed once
  and sends once.
  - Void a gift: "Why it is being voided is required" (`donation-void`).
  - Drop a vendor: "Why are they being dropped? is required" (`blank-submit-slice-c`, fresh dialog;
    also `vendors`).
  - Void a bill: "Why was this bill never owed? is required" (`invoice-void`).
  - Credit note: "What is the credit for? is required" (`invoice-void`).
  - Reverse a payment: "What happened? is required" (`invoice-void`).
  - Conduct note: "Add a note is required" (`staff-conduct-notes`, and `blank-submit-slice-d` on a
    fresh form).
  - Meal correction: "Why the figures are being changed is required" (`meal-correction`).
- Credit of 0: "How much is being credited? must be more than 0", red, `aria-invalid`, and the
  accessible description is set. `creditMock` is not called; a later 400 sends once (`invoice-void`).
  The `form-wrapper` unit tests cover 0 refused, -5 refused, 0.5 allowed, and an empty non-required
  box allowed.
