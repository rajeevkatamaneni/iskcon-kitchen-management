# T-154 — the three screens that can be refused a wrong-family unit now show the line naming the ingredient

**Files changed** (all inside the contract):
- `frontend/app/inventory/[id]/page.tsx`: the page's `actionError` block now shows the field-error list under `ErrorNotice`. This is where a refused stock adjustment lands.
- `frontend/app/donations/new/page.tsx`: the same list under `ErrorNotice`.
- `frontend/components/IngredientRequestForm.tsx`: the same list under `ErrorNotice`. The new-request and edit-request pages share this form.
- `frontend/__tests__/unit-refusal-names-ingredient.test.tsx` (new): one test per screen.
- `docs/work/proof/T-154.md` (this file).

The three existing test files I was granted were not edited. They still pass (see below). `ErrorNotice` and the orders page were not touched. `docs/work/DISPATCH.md` was already modified before I started, and that change is not mine.

**Field keys found** (read-only in the backend):
- All three endpoints refuse through `IngredientUnits.requireSameFamily`: `InventoryItemService:327` for the adjustment, `DonationRecorder:77` for the gift, and `IngredientRequestService:451` for the request. It sends one field error. The **key is the ingredient's own name** (`ref.name()`, e.g. `Ghee`), not `unit` or `lines[0].unit`. The message is "Ghee is measured in L, and there is no way to turn Kg into L."
- The same list also carries bean-validation errors from `GlobalExceptionHandler.handleValidation`. Their keys are Java field paths (`donorName`, `ingredients[0].quantity`). Their messages are whole sentences written for a person ("Enter how much to add or take away.").

**What I chose to show: the message only, never the key.** For the unit refusal, the key would print "Ghee: Ghee is measured in L…", the name twice. For validation errors, the key is a path nobody should read. The order screen shows the key because its keys identify order lines, so copying it as-is would have been wrong here. List items are keyed by position, since two lines can name the same ingredient. The list sits in the same block as the error box.
