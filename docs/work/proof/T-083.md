# T-083 — a correction now reverses every dish before any dish is re-drawn

`ServedMealService.correct` looped `changed` calling one `applyCorrection` per dish, and that method
reversed *that* dish and immediately re-drew it. Across dishes the guarantee its own javadoc states
did not hold: a lunch of two rice dishes swapping figures (khichadi 400 → 640, pulao 640 → 400, net
rice unchanged, no spare rice on the shelf) was refused with `KMS-400042` when the rising dish was
reached first, and succeeded when the falling one was — the outcome depended on `mp.ready_by`.

`applyCorrection` is now two methods driven by two passes over `changed` inside the one existing
transaction:

- `markAndReverse` (pass one) — writes the `meal_plans` row (the `original_*` preservation, status,
  figures, the `cookedAt` rule) and calls `consumptionService.reverse`, returning that dish's
  reversal count into a `Map<UUID, Integer>`.
- `redrawAndRecord` (pass two) — calls `consumptionService.consume` for every dish that is not
  `notMade`, then files the audit entry with `correctedSnapshot(dish.id(), reversed)`, still read
  back from the row and never rebuilt from the request (README lesson 2), carrying the count
  collected in pass one.

Nothing else moved: the same SQL, the same `cookedAt` rule, the same `compensateAllFor` skip of
hand-corrected draws, the same single `@Transactional`.

**Files changed:** both inside the contract, and nothing else.

- `backend/src/main/java/org/iskcon/kms/meal/ServedMealService.java` — in contract.
- `backend/src/test/java/org/iskcon/kms/meal/MealCorrectionIT.java` — in contract.

`ErrorCode.java` was not opened; no new code was needed. `git status` at the end of the task shows
ten other modified files (`communication/`, `shift/`, `audit/`, `frontend/`, `DISPATCH.md`,
`ErrorCode.java`) — those are T-084, T-085 and the coordinator, untouched by me.
