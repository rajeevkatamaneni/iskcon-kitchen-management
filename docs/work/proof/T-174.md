## The `Field` change, and `undefined` versus `false`

`Field` now adds `required: true` to the props it hands its child, and only when it was given `required`. The render-props type has `required?: true`.

What React 18.3.1 renders (checked with `renderToStaticMarkup`):

```
undefined: <input/>
false:     <input/>
true:      <input required=""/>
own true then spread {required: undefined}: <input/>
```

So `undefined` and `false` render the same when they come last. But a key holding `undefined` still wipes out a `required` the child set before the spread (`<input required {...props} />`). **I chose neither. When `Field` isn't required, the key is left out.** No child does that today. The new test "does not take away a required the control sets for itself before the spread" guards it.

## The coordinate proof, client half

The new test types both coordinates, clears latitude and presses Add temple. Only "Latitude is required" appears, and nothing is provisioned. It then clears longitude and presses again. Both are named, and still nothing is provisioned. Then it types both again, and the save goes with 13.0098 and 77.5511. Because `provisionTenant` is never reached while a box is blank, `Number("")` is never built into a payload. The reversed picker test proves the same for boxes that were never typed in.

**`badInput` can't be simulated in jsdom, so it isn't tested.** jsdom 25.0.1 cleans a half-typed number to "" and never sets `badInput`:

```
"12." -> value "" badInput false valueMissing true
"1e" -> value "" badInput false valueMissing true
"-" -> value "" badInput false valueMissing true
"abc" -> value "" badInput false valueMissing true
"13.01" -> value "13.01" badInput false valueMissing false
jsdom 25.0.1
```

A test typing "12." would only repeat the blank case under another name. In a real browser "12." sets `badInput`, and `Form` refuses that too. That claim rests on reading `Form` and `formMessages.ts`, not on a test.

What went red is the new `Field` test and every reversed test. Why the rest stayed green:
- "leaves required off the box, and out of the props…" asserts an absence, so it passes once the pass-through is gone.
