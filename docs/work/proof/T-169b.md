## Edit mode, per section

One hook, `useEditMode(values, restore)`, is used by all five sections.
- **Edit:** takes a snapshot of what the section shows at that moment and makes its boxes editable.
- **Cancel:** puts the snapshot back and closes the section.
- **A Save the server accepts:** closes the section.
- **Closing, either way:** remounts the section's `Form`, so a red sentence from a refused Save cannot outlive a Cancel.

Every section except Appearance works the same way:
- **Read-only boxes:** inputs get `readOnly` and a sunken fill (`read-only:bg-sunken`). They stay focusable and copyable, and a screen reader says "read only". The provider `<select>` has no read-only state, so it is `disabled` with the same fill.
- **Footer:** a quiet **Edit** at the right. Once pressed, it becomes **Cancel** then **Save**, secondary first as §4 says. Save submits the section's `Form` from outside it with `form=`, so the form holds only the boxes. That way no Test, Send or Reveal button can submit it, and pressing Enter in the test-number box cannot save the account.
- **Replace** (on the gateway secret and the WhatsApp token and secret) is an edit, so it shows only after Edit.
- **Test connection, Send a test message and the templates button** hide while their section is being edited. They act on what is saved, not on what is being typed.

**Two sections can be open at once, deliberately.** Each Save sends only its own section, so one section's button can never commit another. That is the accident the rule is for. Allowing only one open section would force a choice when someone presses Edit on a second while the first holds typing. Either the typing is dropped without a word, or the other Edit buttons are greyed out with no reason given. The test "lets two sections be open at once, and each Save sends only its own" pins this.

The shared `Form` is used in every section, and a box that is wrong is named in red:
- **Payment gateway:** Key ID is `required`, and so is the key secret whenever it is being typed. The secret box had no label at all, so a blank one would have read "This field is required". It now has a `<label>`. The disabled check on blank boxes is gone; Save is disabled only while something is in flight.
- **WhatsApp:** both ids are `required`. The token and the app secret are `required` whenever they are being typed, which means on a first connection and while replacing them. The disabled check on blank boxes is gone. For an unconnected temple the button still reads **Connect**, as it did before.
- **Email:** not required, because an empty box means a reply reaches the platform. `type="email"` refuses anything that is not an address.
- **Volunteer messages and Warnings:** `required`, `min` and `max` are on each box. These replace the sentences each box printed as it was typed ("A cap is between 1 and 20 messages.", "A warning is between 1 and 365 days.") and a Save greyed out while a box was out of range. Two checks said the same thing, so one is left. Volunteer messages still greys Save while nothing has changed, which is a different reason. The unit ("days", "a day") now sits in a wrapping row, and the red sentence drops onto its own line below it instead of squeezing into the 7rem box.

## The templates button

It is under a new "Message templates" heading, shown only when WhatsApp is connected. Its label comes from `templatesPending` and `templatesSubmittedAt`, checked in this order:

- **Account changed** (whatever the counts are), primary: "Templates not yet sent to your new WhatsApp account"
- **Changed and refused both waiting**, primary: "N templates waiting to go to Meta". The two numbers are added, since they never overlap.
- **Changed only**, primary: "3 templates changed since they were last sent", or "1 template changed since it was last sent"
- **Refused only**, primary: "2 templates Meta did not accept last time", or "1 template Meta did not accept last time"
- **No recorded send and nothing else waiting**, primary: "Templates not yet sent to Meta"
- **Nothing waiting**, quiet: "Templates last sent to Meta on 16 Aug 2026". The date comes from `templeDay`, day first, in the temple's clock.
- **While sending:** "Sending templates to Meta…". The button is disabled with `aria-busy`, and "This can take a minute or two." shows beside it. Edit and Send a test message are disabled too. A ref guards against a second press.
- **After it finishes:** the answer's settings replace the view. The status reads "Templates sent to Meta." or, if something is still waiting, "Sent to Meta. Some templates still need attention." A refusal shows as an alert beside the button.

Other screen changes:
- The old line "Your message templates went to Meta on …" is gone. The date now lives only in the button. The line "Until Meta approves a template, messages using it go by SMS." stays under the heading.
- While editing, a line beside Save says "Saving does not send templates to Meta." on a connected temple, and "Connecting also sends your message templates to Meta." on an unconnected one.
- Two hints changed, because read-only mode has no Save or Connect button to press: "Press Edit and save your keys first. Save checks your keys with Razorpay…", and "Press Edit and connect your account first. Then this sends…". The WhatsApp status line now reads "Press Edit, enter the four values below, then press Connect."

`refusedTemplates` and `templatesPending` are treated as present. Where either is missing, it falls back to `[]` and all-zero; that is there only for the optional type.

## The refused list

"What Meta said about each template" lists each entry as a badge, the template name, and its reason. Refusals come first and notes last.
- `REFUSED`: "Refused" in a warning colour, with the stored reason.
- `NOT_REACHED`: "Not reached" in a warning colour, with the stored reason.
- `HELD_UNDER_ANOTHER_CATEGORY`: "Note" in grey, with the stored reason plus "Sending again cannot change this." It is not treated as waiting: a temple with only notes keeps the quiet button.
