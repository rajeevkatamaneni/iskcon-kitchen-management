## What was wrong and what changed

1. **Tooltip.** Measured the cause first. On a fresh load at 390 the tip already fitted (right edge 381.9). The verifier's 397.9 comes from opening the tip at 1280 and then narrowing the window. The window's `resize` event fired while the tick was still at x 309, then the page re-rendered for its narrow layout and moved the tick to x 325. The tip kept the slide it had worked out for 309. The fix, in the shared component: while a tip is open, it checks once per frame whether its control has moved sideways or the window has changed size, and refits only when one has.
3. The invoices list pill now reads "Difference ₹300" (it used to say "Variance ₹300"). I first tried "Difference ₹300 more", matching the invoice page's "more than received". It pushed the Due date onto two lines at 1024 (measured), so the sign carries the direction, as it did before.
4. On the Partly delivered tab, Ordered and Received now use the same `inLineUnit` as Still owed: "4 bags (100 Kg) | 2 bags (50 Kg) | 2 bags (50 Kg)". The "… came 12 Sept" note on the Expected tab uses it too.
5. "(required)" is now on Received by, drawn exactly like the uploads draw it (`ml-1 text-ink-muted`). Amount and Paid on were required and unmarked in the same way, so they got it too. `Form` still names the field without it: "Received by is required".
6. Cost per serving, reworded with the ux-writing skill. The heading now reads "Estimated, materials only — from list prices, or the market rate". The detail line reads "… have no list price or market rate, so they are left out." The "n ingredients have no known price" notice is unchanged.
7. The sheet's date formatter is now `ofPattern("d MMM yyyy", Locale.UK)`. With no locale it used the JVM default, US English, which writes "Sep". Checked month by month on JDK 21: Locale.UK gives exactly what Node's en-GB gives (Jan … Aug, Sept, Oct … Dec). The recipe card's date comes from the same formatter, so it changes the same way.
