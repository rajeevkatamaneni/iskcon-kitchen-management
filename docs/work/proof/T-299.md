# T-299: a PO number never breaks at its hyphens, an open delivery history gives way before short columns do, and one unnamed pack is written once

## Files changed (all inside the contract)

- `frontend/components/ds/table.ts`
  - New `withWholeWords` and `joinHyphens`. A word joiner (U+2060) goes after each inside hyphen of a word that has a figure in it. This runs in `fitTable` before the 1024 check and before any measuring.
  - `ADDRESS` is now a constant, shared with `withAddressBreaks`. It says what an address is; its behaviour did not change.
  - The copy handler also strips the joiners.
- `frontend/components/DeliveryHistory.tsx`: each piece of a history line is `whitespace-nowrap lg:whitespace-normal`. It was `whitespace-nowrap`. There is a comment saying why.
- `frontend/components/RecordDeliveryPanel.tsx`
  - New `repeatsPack`.
  - `inLineUnit` drops the bracket for one unnamed pack.
  - The stock amount beside the box is dropped in the same case.
- `frontend/__tests__/table-rule.test.ts`: 4 new tests.
- `frontend/__tests__/record-delivery-panel.test.tsx`: 2 new tests.
- `frontend/__tests__/delivery-history.test.tsx`: 1 new test.
- `docs/work/proof/T-299.md`: this file.

Not touched: `app/globals.css`, `app/deliveries/page.tsx` and `app/invoices/page.tsx`. Each was fixed at the shared source instead. The other test files were run, not changed.

## Causes

- **N2, and the Order column in C-1.** Chrome treats the hyphen in "PO-2026-0054" as a place it may end a line. CSS has no switch that turns this off (`hyphens` only governs soft hyphens). The fitter also measured each column's narrowest width with the browser's own line breaking. So once a short cell was allowed to wrap (`data-kms-stack="words"`), it counted "PO-" as the widest piece and narrowed the column to fit it.
- **C-1, Item column.** Each piece of a history line was `whitespace-nowrap`. That made "Received by: Lalita Devi Dasi" the narrowest the Item column could go, which was 262–267px. With no room left, the fitter took the width out of the short columns instead.
- **C-2.** `inLineUnit` always wrote `(stock)` after the count. For one pack with no name, that bracket is the pack's own label again.

## Choices made by the rule's logic (Q-18, the lesser evil)

1. **Only a word with a figure in it is joined.** That covers "PO-2026-0054", "INV-2026-17" and "VERIFY2-C". A compound of words such as "Top-up" or "VERIFY-A" still wraps at its hyphen, which is how ordinary text ends a line.
   - I first joined every hyphenated word, and measured it. /inventory at 1024 then ran 4px past its box (682 in 678), and the box scrolled sideways, because "VERIFY-A" in Location could no longer give way.
   - Limited to words with figures, /inventory is identical before and after.
2. **Joiners are added at every width, not only from 1024 up.** A code should not break on a phone card either.
3. **The history gives way only from 1024 up,** where it sits inside a fitted table. On a phone card each piece stays whole, as the mock asked ("Received by: Govinda Das" must not split before "Das").
4. **The bracket is dropped only when it repeats the pack.** "1 × 500 gm" loses it, "2 × 500 gm (1 Kg)" keeps it (the conductor's earlier ruling), and "1 bag (25 Kg)" keeps it. The test is "one pack with no name", counted in packs rather than by comparing text, so a "0.5 Kg" label over a "500 gm" total counts as a repeat too.
5. **Copying and finding still work.** The joiners are invisible. Copied text has them stripped. In Chromium, `window.find("PO-2026-0026")` on /invoices returned `true` with the joiners in place:

   ```
   {"text":"PO-⁠2026-⁠0026","hasJoin":true,"find":true,"inner":"PO-⁠2026-⁠0026"}
   ```

## Acceptance criteria

- **C-1, short values stay on one line while Item has width to give:** met. See the numbers above.
  - Order 63 → 123, and "PO-2026-0054" is on one line.
  - Still owed 57 → 119, and "2 bags (50 Kg)" is on one line.
  - Owed for is back to 136 on one line in every group.
  - The open history wraps inside the Item column instead.
- **N2, a PO number kept whole in every table:** met. The fix is in the fitter, so it applies to every fitted table. After the fix there are 0 broken codes in 51 runs, down from 5 before.
- **C-2, no doubled size for an unnamed pack:** met. Checked by unit test and on the running app. Named packs and multi-pack totals keep their brackets.
- **No regression on T-278's tables:**
  - No word broken mid-letter, before or after.
  - No sideways scroll on any page at any of the three widths.
  - No clipped control.
  - The two changes that are not improvements are listed below.
- **tsc, eslint, vitest:** clean, with the output above. Each fix goes red under the control.
